# CNIL 목록 날짜와 기간 탐색 개선 (2026-10-23)

이 변경은 CNIL 범위 밖 카드마다 상세 본문을 내려받던 비용을 줄입니다. 오래된 카드나 오래된 페이지를 기간 전체 탐색의 종료 근거로 사용하지 않습니다. 실제 예약 완료나 출처 전체 수집 완료를 선언하지 않습니다.

## 실제 공식 HTTP 확인

직접 GET한 목록 첫 페이지와 `?page=15`, 첫 과거 카드 상세가 모두 HTTP 200이었습니다. URL·응답 SHA-256·카드 표본은 `cnil-range-http-evidence-20261023.json`에 기록했습니다.

- 첫 목록 25개 중 13개는 2026-09-21~2026-10-23 안, 12개는 밖입니다.
- 15번 목록 25개는 모두 범위 밖이며 2024-03-27~2024-01-30입니다. 첫 카드의 상세 표시 날짜도 2024-03-27입니다.
- 카드 날짜는 `.list-inner .attributes p.date`입니다. 같은 카드의 제목 링크와 함께 관측값으로 보존합니다.
- 공식 공개 form의 `sort_by` 옵션은 `field_type_article_target_id` 하나입니다. `sort_order`의 ASC/DESC만 보고 날짜 정렬을 단정하지 않습니다. 고정글 정책도 입증하지 못했습니다. 따라서 다음 페이지 링크를 계속 따릅니다.

## 변경과 보존

Python과 Edge는 단일·정상 카드 날짜가 요청 범위 밖일 때 개별 카드만 제외합니다. `listing_date_only`로 기록하며 상세 원문을 읽었다고 표시하지 않습니다. Edge는 연속 범위 밖 카드를 한 단계에 묶어 처리하여 기사별 HTTP와 큐 반복을 줄입니다. 날짜 누락·유효하지 않은 날짜·복수 날짜는 상세 확인 경로를 유지합니다. 상세를 읽은 자료의 카드 날짜와 상세 날짜가 충돌하면 게시일 미확정·검토 필요로 남깁니다.

Edge의 기존 CNIL 캐시 행은 현재 페이지에서 한 번 새 목록으로 갱신합니다. 이전 행 순서의 offset을 새 행에 옮기지 않으며, 실패·미확정 카운터와 기존 기간은 보존합니다. 별도 backlog 작업은 이 목록 날짜 최적화를 적용하지 않고 기존의 정확한 실패 URL 재시도를 유지합니다.

Python도 CNIL의 목록 순회 완료와 기간 전체성 입증을 분리하며 `coverage_complete=false`를 유지합니다. 기존 Edge는 원래 모든 출처에서 false입니다. 미완료 backlog 삭제나 완료 checkpoint 생성은 추가하지 않았습니다.

Edge의 기존 종료 경로는 rows 삭제·page 시작점 복원 후 다음 enqueue에서 새 목록을 읽습니다. root가 읽기 전용으로 확인한 실제 배포 `collector_edge_take`는 until을 오늘로 확장하므로, enqueue가 기존 state를 유지한다는 이유만으로 SQL을 변경하지 않았습니다. 재개 계약 테스트는 갱신된 until과 기존 since/unknown_dates/failures 보존을 확인합니다. 실제 다음 예약 실행 검증은 별도입니다.

## 검증

- 기존 구현에 새 회귀 테스트를 대입하면 Python 카드 날짜/불필요 상세 읽기, Edge 날짜 관측/필터/캐시 갱신 테스트가 실패합니다.
- 수정 후 Python collector 98개, Edge adapter/runtime 22개, 앱 137개 검사가 통과했습니다.
- `npm run validate:data`: 팀 데이터 및 21건 형식 검사 통과. 사실 확인이나 사람 승인으로 해석하지 않습니다.
- PDF 테스트의 canvas/Path2D 경고는 기존 텍스트 추출 경로에서 발생합니다. PDF 렌더링 성공을 주장하지 않습니다.
- 배포·운영 DB 쓰기·원격 push·예약 변경은 수행하지 않았습니다.

날짜 정렬 및 고정글 정책, 모든 목록의 전체성은 여전히 미입증입니다. 이번 수정으로 목록 전체 순회는 더 적은 요청으로 진행하지만 임의 조기 종료로 누락 위험을 숨기지 않습니다.
