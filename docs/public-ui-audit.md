# 공개 화면과 작업자 화면 점검 — 2026-10-10

실제 Chrome 브라우저에서 링크·버튼을 클릭했습니다. 공개 홈, 검색, 법제 비교, 주간호, 동향 상세와 기존 작업자 홈·검수 자료·팀 가이드·번역 검토 경로를 확인했습니다. 데이터 변경이나 승인·발행은 수행하지 않았습니다.

## 발견하고 수정한 문제

| 문제 | 수정 |
|---|---|
| 화면마다 메뉴 이름과 경로가 달랐고 법제와 비교가 같은 경로를 중복 표시 | 공통 메뉴를 동향·주간호·동향 검색·법제 비교로 통일 |
| 주간호 전체 보기에서 일반 검색으로 이동 | `/public/weekly`에 별도 목록과 미발행 안내 제공 |
| 홈 동향에서 자기 상세 대신 태그 검색으로 이동, 홈과 검색의 예시가 달랐음 | 공통 예시 6건을 사용하고 개별 상세 경로 추가 |
| 필터 CSS가 실제 버튼 위치와 달라 브라우저 기본 버튼으로 표시 | 필터 그룹 내부 버튼에 관측소 스타일 적용 |
| 검색 입력 즉시 결과 변경, 검색 버튼은 선택 항목만 초기화 | Enter·검색 버튼으로 제출하고 URL에 검색어 저장 |
| 새로고침·뒤로 가기에서 검색어가 유지되지 않음 | URL의 검색어와 입력·검색 결과 동기화 |
| 여러 검색 단어 중 하나만 포함해도 키워드 결과에 노출 | 키워드 모드는 모든 입력 단어를 포함하도록 수정 |
| 정렬 후 다른 동향이 선택될 수 있음 | 배열 순번 대신 동향 ID로 선택 유지 |
| 선택 동향·번역 전문 패널이 아래에 있어 클릭 결과를 놓칠 수 있음 | 해당 패널로 스크롤 이동 |
| 법제 기준 변경이 비교 카드에 반영되지 않아 동작이 불분명 | 카드의 기준 제목도 변경, 전문 상태에서 기준을 누르면 요약 전환 |
| 1개국 선택 시 불필요한 빈 비교 열 | 1·2·3개국에 맞는 열 배치 적용 |
| Windows 국기 이모지가 글자로 표시되어 가독성이 나쁨 | 국가 코드 배지로 표시 |
| 공개 화면에서 기존 작업자 화면으로 가는 경로 없음 | 공개 하단과 작업자 사이드바에 상호 이동 링크 추가 |
| 공개 페이지 탭 제목이 검토 보드로 표시 | 공개 영역의 페이지 메타데이터 분리 |
| 모바일 필터가 결과를 너무 아래로 밀어냄 | 모바일 필터 펼치기·접기 추가 |

## 경로와 기존 작업자 화면

| 경로 | 역할 |
|---|---|
| `/` | 기존 작업자 홈. PR Preview에서는 제출물 탭을 제공. 기존 화면 유지 |
| `/team` | 검수 전 자료를 포함한 목록. 로그인 없는 읽기 전용 |
| `/guide` | 팀 온보딩 가이드 |
| `/legal-translation` | 팀 제출 번역의 검토 화면. 이 브랜치에 번역 파일이 없으면 빈 상태 |
| `/public` | 공개 관측소 시안 |
| `/public/search` | 예시 동향 검색 |
| `/public/laws` | 법제 비교 시안 |
| `/public/weekly` | 주간호 목록, 현재 발행 자료 없음 |
| `/public/trends/sample-1` 등 | 예시 동향 상세 |

작업자 페이지를 공개용으로 덮어쓰거나 루트 경로를 교체하지 않았습니다. 현재 `/`와 `/team`은 ReviewShell의 검수 실행 권한을 전달하지 않으므로 승인·반려 버튼이 표시되지 않습니다. 기존 서버 검수 함수는 남아 있으나, 이 UI 작업에서 검수 기능을 완성했다고 주장할 수 없습니다. 이전 배포의 `/team`에서 출처 3개·법제 7개·비교 기준 17개를 확인했습니다. 로컬은 실제 Supabase 접근 권한 없이 샘플로 검사했으므로 실제 데이터 수 검증과 구분합니다.

## 아직 구현되지 않은 부분

- 공개 동향은 예시 6건이며 실제 Supabase의 발행 동향과 연결되지 않았습니다.
- 주간호·법률 한국어 번역 전문·17개 기준별 법제 요약은 등록·검수된 자료를 표시하도록 연결하는 후속 작업이 필요합니다.
- 관련 개념 검색은 미리 지정한 표현을 확장하는 시연이며 임베딩 기반 의미 검색이 아닙니다.
- 예시에는 원문 링크가 없습니다. 외부 원문 접근, 승인·발행·권한 변경·실제 수집 파이프라인은 이번 브라우저 검사에서 실행하지 않았습니다.
- 검색어는 URL에 저장되며 국가·기간·자료 유형·정렬은 현재 화면 상태입니다. 새로고침하면 필터는 초기화됩니다.

## 검사와 재실행

기존 단위 테스트 13건, 자료 형식 검사, 타입 검사 및 배포 빌드를 통과했습니다. 기존 번역 검토 CSS의 `align-items: end` 호환성 경고는 남아 있으며 빌드를 막지 않습니다.

`scripts/verify-public-ui.cjs`는 공개 메뉴, 홈의 모든 동향·토픽 링크, 검색 제출·새로고침·뒤로 가기·지우기, 모든 필터, 법제 17개 기준·7개 국가·1~3개국 선택, 작업자 화면의 필터·검색·가이드 링크, 390·768·1024·1440px 화면과 브라우저 실행 오류를 확인합니다. 브라우저 테스트용 Playwright 설치가 필요합니다. 앱의 운영 의존성에 추가하지 않았습니다.

PowerShell 예시:

```powershell
$env:AUDIT_BASE_URL = 'http://localhost:3100'
# 별도 설치된 Playwright 모듈을 사용하는 경우에만 지정
$env:PLAYWRIGHT_MODULE_PATH = 'C:/사용하는경로/node_modules/playwright'
# 설치된 Chrome을 사용하는 경우에만 지정
$env:CHROME_PATH = 'C:/Program Files/Google/Chrome/Application/chrome.exe'
node scripts/verify-public-ui.cjs
```

결과는 임시 폴더의 `globaltrend-ui-audit.json`에 저장됩니다. `AUDIT_REPORT`로 결과 경로를 지정할 수 있습니다. 로컬 브라우저 점검 중에는 같은 `.next` 폴더를 쓰는 개발 서버와 빌드를 동시에 실행하지 마십시오. 환경 변수를 설정한 배포용 빌드 또는 Preview를 사용하십시오.
