# 초안 작성 파이프라인 통합 수정 계획

> **Goal:** 한 PR에서 운영 초안 차단 조건을 사용자 기준에 맞게 정리하고, #151의 SQL 오류를 바로잡는다.

**Architecture:** 기존 claim → source revision 검토 → server seal → submit 경로와 사람 검수 대기 상태를 유지한다. 문구 채우기·추출 상태·연결 링크 접근 실패 때문에 작성 자체를 막는 조건은 풀고, 실제 원문에 있는 근거·최신 판본·중복 방지·임대 소유권·기존 원고 보호는 유지한다.

**Tech Stack:** Supabase PostgreSQL migrations/RPCs, 기존 JSON 작성 정책, 작업자 지침 문서.

## 결정된 범위

- #151의 31개 허용 출처와 내부 검토기록 분리는 보존한다.
- `ai_ready`, 날짜 존재, 모든 첨부 열람, `full_official_body`, 최소 글자 수 12/20 및 700자 사유는 초안 제출의 필수조건으로 쓰지 않는다.
- 실패 작업은 3회에서 영구 제외하지 않는다. 동일 항목의 즉시 재시도 루프는 `updated_at` 기반 대기시간으로 막고 다른 작업은 계속 처리한다.
- 400MB 저장 안전선, 현재 판본·실제 인용·중복/기존 원고 보호·유효 lease·검수 전 draft 상태는 유지하되, 저장 안전선은 빈 큐처럼 숨기지 않고 오류로 드러낸다.
- 내부 coverage의 “해당 없음”과 이유는 `writing_review`에만 저장하고 원고 본문으로 유출되지 않게 한다.

## 작업 순서

1. 아직 미적용인 #151 migration의 분기문 치환 오류를 수정한다.
2. 해당 migration에서 source allowlist, readiness/date/attachment/full-body/문구 길이/attempts/storage 동작을 한 계약으로 정렬한다.
3. 작성 지침과 전수 감사 문서를 실제 코드 동작에 맞춰 갱신하고 남는 보호조건 및 주간호 날짜 필터를 설명한다.
4. diff·migration history·운영 함수 정의를 대조해 검증 근거를 남기고, 이 변경을 PR #149 한 건에 통합한다.

## 검토 초점

- 제한된 원문으로도 확인 가능한 범위만 근거 삼아 draft 저장이 가능한가.
- 실패 한 건이 다른 큐 작업을 멈추거나 3회 뒤 영구히 사라지지 않는가.
- public report body에 내부 review checklist나 “해당 없음”이 들어가지 않는가.
- 기존 보고서, 다른 revision, 사람 검수/발행 상태를 덮어쓰지 않는가.
- migration 함수 교체가 예상 밖 운영 함수 정의를 조용히 덮지 않고, 기준점이 다르면 설명 가능한 오류로 멈추는가.
