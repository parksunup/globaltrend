# 검토용 웹앱 설계안

## 목적

팀원이 실제 데이터를 공개하기 전에 수집 출처, 법제 목록, 비교 기준을 한 화면에서 확인하고 검수할 수 있는 정적 검토 화면을 만든다. 이 단계의 성공 기준은 Vercel Preview에서 화면 구조와 문구를 직접 보고 수정 의견을 낼 수 있는 것이다.

## 범위

이번 단계에 포함한다.

- Next.js App Router 기반의 검토용 화면
- 좌측 내비게이션: 수집 출처, 법제 목록, 비교 기준
- 상단 상태 필터: 전체, 검수 전, 검수 중, 승인, 공개
- 중앙 목록: 항목명, 설명, 출처 URL, 현재 상태
- 우측 검토 패널: 선택 항목의 상세 정보, 검토 메모, 공개 여부
- 실제 Supabase 대신 타입이 명확한 샘플 데이터
- Vercel Preview에서 확인할 수 있는 반응형 레이아웃

이번 단계에서 제외한다.

- 로그인·팀원 권한
- Supabase 조회·수정
- 실제 크롤러
- Codex 초안 생성
- 법령 원문 번역
- 공개 사용자용 검색 화면
- 데이터를 실제로 공개 상태로 전환하는 mutation

## 사용자 흐름

1. 팀원이 Preview를 연다.
2. 좌측에서 출처, 법제, 비교 기준 중 하나를 선택한다.
3. 상단 상태 필터로 검수 대상을 좁힌다.
4. 중앙 목록에서 항목을 선택한다.
5. 우측 패널에서 상세 정보와 검수 메모를 확인한다.
6. 화면 구조와 문구가 확정되면 다음 PR에서 Supabase 연결을 검토한다.

## 화면 구조

- **헤더**: 서비스명, 현재 화면명, Preview 표시
- **사이드바**: 세 가지 데이터 유형과 각 항목 수
- **필터 바**: 상태 필터와 검색 입력창
- **목록 패널**: 선택 가능한 카드 또는 표 행
- **상세 패널**: 제목, 설명, 공식 URL, 상태 배지, 검토 메모, 공개 조건

검토 화면은 데스크톱에서 3열로 표시하고, 좁은 화면에서는 사이드바·목록·상세 패널을 세로로 쌓는다.

## 상태 모델

화면 샘플 데이터는 다음 상태를 사용한다.

- `unreviewed`: 검수 전
- `in_review`: 검수 중
- `approved`: 승인
- `published`: 공개

이번 단계에서는 상태를 변경하지 않는다. 상태 배지는 읽기 전용이다.

## 샘플 데이터

출처:

- EDPB 뉴스·보도자료
- OECD 개인정보·데이터 보호
- CJEU/CURIA 보도자료·판결 안내

법제:

- 한국 PIPA
- 일본 APPI
- 중국 PIPL
- EU GDPR
- UK GDPR
- 캘리포니아 CCPA
- 싱가포르 PDPA

비교 기준은 한국·일본 비교표의 17개 항목 중 일부를 대표 샘플로 보여주고, 목록에는 전체 항목 수를 표시한다. 실제 전체 기준 데이터는 PR #3의 시드 SQL에서 관리한다.

## 컴포넌트 경계

- `ReviewShell`: 전체 3열 레이아웃과 선택 상태 관리
- `ReviewSidebar`: 데이터 유형 전환
- `ReviewToolbar`: 검색어와 상태 필터
- `ReviewList`: 현재 유형의 샘플 항목 목록
- `ReviewDetail`: 선택 항목 상세·검수 정보
- `StatusBadge`: 상태별 색상과 한국어 라벨
- `sample-data.ts`: 화면 전용 타입과 샘플 데이터

Supabase 클라이언트는 이번 단계에서 만들지 않는다. 다음 단계에서 서버 컴포넌트 조회와 RLS 권한을 별도 PR로 연결한다.

## 검수 기준

- 첫 화면에서 현재 작업 목적이 ‘검토’임을 알 수 있어야 한다.
- 세 가지 데이터 유형을 한 번에 이해할 수 있어야 한다.
- 선택된 항목과 현재 상태가 시각적으로 구분되어야 한다.
- 공식 원문 URL과 공개 여부가 상세 패널에 보여야 한다.
- 샘플 데이터와 실제 데이터가 혼동되지 않도록 Preview 전용 표시를 둔다.
- 좁은 화면에서도 목록과 상세 정보에 접근할 수 있어야 한다.
