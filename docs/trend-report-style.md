# 개인정보 동향 보고서 작성 기준

기준 ID: `privacy-report-ko-2026-10`. 모든 출처의 개별 동향과 주간 보고서에 적용합니다. 주간호에 선정하지 않은 자료도 동일하게 작성합니다.

## 참고 자료와 적용 범위

사용자가 제공한 「2026 개인정보 주간동향 제39호·10월 2주」 PDF 14쪽을 확인했습니다. 물리 3쪽의 목록표와 4~8쪽·10~13쪽의 기사별 제목, 강조 요약, 항목별 설명, 하단 출처 구조를 참고합니다. 문체와 구조를 따르며 해당 호의 기사나 로고를 우리 동향의 근거로 가져오지 않습니다. PDF는 저장소에 포함하지 않으므로 아래 기준과 저장소의 전수 편집본만으로도 작성할 수 있게 합니다.

## 수집부터 제출까지

1. 수집기는 공식 원제·본문·날짜 관찰·URL·원문 판본·연결 문서를 보존합니다. 보고서체로 원문을 변형하거나 AI를 호출하지 않습니다.
2. Codex는 정확한 원문 판본과 읽은 범위를 확인하고 아래 보고서체로 한국어 초안을 작성합니다.
3. 출처·날짜·수치·금액·조건·예외·법적 단계를 원문과 대조하고, 작성자 해석과 미확인 범위를 각 검수 필드에 기록합니다.
4. 형식 검사를 실행한 후 기존 검수·승인·발행 절차로 제출합니다. 통과하지 못한 원고는 수정합니다.

## 공통 원고

- 제목: `국가·기관, 대상과 구체적 조치`. 발표·제정·개정·의견수렴·최종 승인·조사 개시 등 실제 단계를 씁니다. 같은 기사에 초안과 최종본이 함께 있으면 제목과 본문에서 각각 구분합니다.
- 핵심 요약(`summary_ko`): 주체·주요 조치·대상 또는 중요한 조건을 한 문단으로 압축합니다. `발표`, `규정`, `요구`, `권고`, `추진`, `시행 예정` 등 보고서체로 종결합니다. 상세 본문 전체나 `주요 내용` 목록을 여기에 붙이지 않습니다.
- 상세 본문(`details_ko`): 강조 요약 아래에 소제목 없는 `- 설명` 항목을 이어 쓰고, 항목 사이에 빈 줄을 넣습니다. 각 문단에 배경·대상·일정 등의 제목을 임의로 붙이지 않습니다. 원문 조항 번호처럼 실제 구획이 필요한 경우에만 그 구분을 본문에 유지합니다. 배경·대상 → 핵심 조치·판단 → 조건·예외 → 일정·후속 절차 순서를 기본으로 하되 원문에 없는 항목은 만들지 않습니다. 복잡한 정책은 충분히 설명하고 짧은 공지는 확인한 범위에서 간결하게 씁니다.
- 문체: `했다`, `설명한다`, `~합니다`의 반복을 줄이고 `발표`, `설명`, `안내`, `요구`로 정리합니다. 기관의 평가와 주장은 주체를 밝힙니다. 기관·법률·전문용어는 처음에 필요한 설명과 약어를 붙입니다.
- 출처: 공식 원제·기관·원문 게시일·공식 URL을 보존해 기사 하단에 표시합니다. 사건일·선고일·공포일·시행일을 게시일과 섞지 않습니다.

## 원고 전체를 읽는 윤문 단계

형식을 맞춘 뒤에는 제목·핵심 요약·본문을 한 편의 글로 이어 읽습니다. 요약을 그대로 반복하는 항목은 삭제하거나 다른 항목과 합치고, 빠진 사실이 없는지 확인합니다. 주체가 바뀌거나 생략되어 독자가 누가 판단·설명·요구하는지 알기 어려우면 주어를 명시합니다. 서로 관련된 내용은 붙여 배치하고, 조건·예외와 그 적용 대상이 떨어지지 않게 합니다. `이에 따라`, `다만`, `이와 별개로` 등의 연결 표현은 원문상 관계가 성립할 때만 사용합니다.

짧은 공지는 항목 수를 채우려고 늘리지 않습니다. 긴 문장은 필요한 곳에서 나누되 법적 조건이나 미확정 단계를 생략하지 않습니다. 윤문 전후의 수치·금액·날짜·기한과 법적 상태를 대조하고, 수정된 21건 전체를 다시 읽어 문장 호응·반복·설명 순서를 확인합니다. 형식 검사와 브라우저 검사는 이 읽기 검토를 대신하지 않습니다.

서식 예시(실제 기사 아님):

```json
{
  "title_ko": "국가 감독기관, 사업자 보호조치 개선 권고",
  "summary_ko": "국가 감독기관, 특정 서비스의 개인정보 보호조치를 점검하고 접근 통제 개선 및 후속 점검 계획 안내",
  "details_ko": "- 공지에서 확인한 서비스와 처리 범위를 설명\n\n- 원문에 명시된 조치와 조건을 설명\n\n- 공지에서 확인한 일정과 진행 단계를 설명"
}
```

위 문안의 빈 내용을 실제 원문 없이 그대로 제출하지 않습니다.

## 사실·해석·검수 기록

독자 본문에는 사실과 필요한 한계를 자연스럽게 설명합니다. `검토 필요`, `일반화하지 않는다`, `원문을 정확히 반영하는지 확인` 같은 작성자용 지시는 본문에서 제거하고 `limitations` 또는 검토 메모에 보존합니다. 판결의 조건·예외·절차상 의미까지 제거해서는 안 됩니다. 예를 들어 환송 사건은 `본안 심리는 후속 절차의 대상`이라고 설명합니다.

개인정보 보호상 의미는 `policy_implications_ko`에 `작성자 해석:`으로 기록하고, 화면에서 제공할 경우 편집자 해설임을 표시합니다. 모든 기사에 해설을 억지로 생성하지 않습니다. 근거별 인용·위치·미확인 전문·이용조건·게시일 불일치와 보류 상태는 기존 검수 필드에 보존합니다. 사실이나 날짜를 확인하지 못했다면 문체가 완성돼도 발행하지 않습니다.

## 저장소 파일과 검사

기존 조사 기록은 `data/trends/fixtures/`에 보존하고, 독자가 읽을 원고는 동일한 `record_id`의 `data/trends/editorial/report-drafts.json`에서 관리합니다. 사람이 읽을 완성본은 `report-drafts.md`입니다. 현재 9출처·21건 전체를 수록하며, 새 표본이 늘면 편집본도 함께 늘립니다. 각 자료의 공식 링크와 메타데이터·근거는 원 조사 기록에 연결됩니다.

```text
node scripts/trend-report.mjs --render
npm run validate:data
```

`--render`는 편집본의 Markdown을 생성합니다. `validate:data`는 수집 표본과 편집본의 ID가 누락·중복 없이 대응하는지와 제목·요약·상세 본문의 형식을 검사합니다. 생성한 Markdown도 커밋합니다.

DB 수집 작업은 `docs/trend-draft-worker.md`의 기존 JSON 계약을 사용합니다. 제출할 JSON을 임시 파일로 저장한 후 다음 명령을 실행하고 수정한 뒤 제출합니다.

```text
node scripts/trend-report.mjs --check <제출할-초안.json>
```

이 명령은 문체·구조의 사전 검사입니다. 인용의 진위·의미·주장과의 대응은 별도로 원문과 대조하고 기존 서버 검사와 사람 검수를 거칩니다. 별도 AI API 비용 없이 Codex가 작성합니다.

## 번역 용어 기준

[프로젝트 용어집](translation/glossary.md)의 사용자 지정 용어를 함께 적용합니다. 컨트롤러·프로세서의 법률상 개념을 유지하고, 싱가포르 data intermediary는 데이터 중개자로 표기합니다. PET·TEE는 독립적으로 읽는 자료의 첫 등장에 한국어 명칭 뒤 영문 약자를 괄호로 병기합니다. 미확정 후보는 원문과 국내 용례를 대조한 뒤 결정합니다.
