# 수동 운영 검증 — 2026-10-21

이 기록은 정기 운영 전체 완료가 아닙니다. 사용자가 등록한 GitHub Actions
Secrets·Variables를 실제 수동 workflow에서 사용했고, 새 공식 원문을 한국어
미검수 초안으로 제출해 운영 검수 화면까지 연결했습니다. 예약 스위치는
`SCHEDULE_ENABLED=false`를 유지했습니다.

## 설정과 수정

- 운영 DB의 기존 출처 9개가 활성 상태이고 이용조건 검토 시각이 기록돼 있음을
  조회했습니다. 사용자 승인에 따라 저장소의 출처 ID와 수집·저장·AI 처리
  스위치를 이 기존 출처에 연결했습니다. 새 출처나 프로젝트는 만들지 않았습니다.
- 수동 workflow에서 `source`를 고를 수 있습니다. `all`과 예약 경로는 출처별
  matrix 작업으로 분리하며 최대 3개를 동시에 실행합니다. 출처마다 기존 요청
  예산·진행 위치·실행 결과를 갖습니다.
- 성공한 void RPC의 `204 No Content`를 JSON으로 해석하다 실패하던 버그를
  수정했습니다. 실제 첫 수동 실행에서 `collector_set_progress` 오류를 재현했고,
  같은 함수의 HTTP 204 정상 응답과 테스트를 통해 원인을 확인했습니다.
- 문서·페이지 처리 한도는 저장된 위치에서 재개하는 `partial`로 구분합니다.
  순환 페이지와 실제 HTTP·DB 오류는 계속 실패합니다. workflow는 `partial`을
  경고와 JSON 결과로 남기며, 범위 완료나 `operation_success=true`로 바꾸지 않습니다.
- CI는 실제 출처를 비활성화하도록 강제하는 대신 예약 스위치가 꺼진 실행이
  네트워크·DB 호출 전에 차단되는지 확인합니다.

## 후속 수정 — PDPC 목록 응답

실패를 다시 재현한 뒤 PDPC 공식 페이지 대신 같은 공식 호스트의 공개 목록
JSON URL을 직접 읽도록 설정을 바꿨습니다. 관리형 환경에서 실제 JSON 10건과
다음 페이지 URL, 첫 기사 본문 7,616자를 읽고 게시일 `2026-09-30`을 확인했습니다.
기존 설정은 GitHub runner에서 HTML에 기대한 섹션이 없어 실패했으므로, 새 직접
JSON 경로도 Actions에서 별도로 확인했습니다. runner 응답은 JSON이 아니었습니다.

목록에 `www.mddi.gov.sg`의 장관 연설 링크가 섞여 있습니다. 이 도메인은 승인된
출처 호스트 목록에 없으므로 요청하지 않도록 하고, 나머지 PDPC 자료는 처리하되
그 링크를 제외한 실행은 `partial` 및 `unapproved_external_listing_links`로
기록하도록 했습니다. 페이지 위치를 이어갈 때 제외된 링크 수도 보존합니다.
임의로 허용 도메인을 추가하지 않았습니다.

이 후속 수정 뒤 수집기 검사 72개와 21건 기존 자료 검증이 통과했습니다. 초기
백필의 기본 범위도 1주에서 달력상 1개월로 바꿨습니다. 마지막 성공일이 있으면
기존대로 3일 중첩해 증분 수집합니다.

GitHub runner에서 직접 재시험한 PDPC API URL은 최종 URL이 그대로였지만 응답 형식이
`text/html`, 본문이 0바이트였습니다. 첫 기사 응답도 0바이트였습니다. 이는 JSON
파서가 정상 원문을 잘못 읽는 문제가 아닙니다. FTC RSS URL은 `http_403`을 반환했습니다.
수집기 probe가 robots.txt와 실제 목록 요청의 실패를 구분하도록 수정했습니다.

새 probe에서 OECD는 robots.txt 다음 실제 개인정보 주제 페이지 요청에서 HTTP 403
(`39553387597`)을 받았습니다. FTC는 GitHub runner가 FTC `robots.txt`를 요청할 때
HTTP 403(`39553513569`)을 받았습니다. 이는 관리형 환경과 다른 응답이며, robots
정책을 우회하지 않았습니다.

관리형 환경의 PDPC 실제 제한 쓰기(`7388f51a-da81-4db9-9c98-b72d76e051d0`)는
목록 10건 중 기간 밖 9건을 확인하고 승인되지 않은 외부 링크 1건은 요청하지
않았습니다. 결과는 `partial`, 새 자료 0건입니다. 이 검증 기간
`2026-10-16~2026-10-21`은 한 달 백필 실행과 별개입니다.

## 한 달 백필 재개 시험

지정된 달력상 한 달 `2026-09-21~2026-10-21`을 모든 출처에 대해 재개 실행으로
이어갔습니다. 첫 실행은 [39553831500](https://github.com/parksunup/globaltrend/actions/runs/39553831500),
두 번째는 [39554488427](https://github.com/parksunup/globaltrend/actions/runs/39554488427),
세 번째는 [39555074137](https://github.com/parksunup/globaltrend/actions/runs/39555074137),
네 번째는 [39555483601](https://github.com/parksunup/globaltrend/actions/runs/39555483601)입니다.
매번 출처별 최대 30개 원문 처리 한도에서 커서를 보존했고, Supabase는 최종 실행에서
약 25.0MB / 400MB로 사전 용량 검사를 통과했습니다.

EDPB, CURIA, CNIL, DPC는 네 실행에서 계속 `document_limit`에 도달해 기간 완료를
검증하지 못했습니다. 네 번째 실행의 각 30개 표본도 모두 지정 기간 밖이었고,
아직 실제 2026-09-21~2026-10-21 자료에 도달하지 못했습니다. DPC 두 번째 실행에서
신규 원문 1건이 저장됐지만 게시일 미확정으로 보류됐습니다. ICO는 목록의 첫 관련
상세 자료에서 `title_or_body_missing`이 반복돼 커서가 해당 항목에 머뭅니다. PPC는
목록 3건의 게시일을 모두 확인하지 못해 보류됩니다. OECD(목록 HTTP 403), FTC
(robots.txt HTTP 403), PDPC(비 JSON 응답)는 모든 재실행에서 실패했습니다.
따라서 이 네 실행은 기간 전체 수집 또는 아홉 출처 운영 완료를 입증하지 않습니다.

후속 수동 백필을 여러 번 실행하지 않고 목록을 더 넓게 처리할 수 있도록 workflow
수동 입력에 출처별 `max_items`(1–100, 기본 30)와 `max_pages`(1–50, 기본 10)를
추가했습니다. Python 실행기가 범위를 검증하고, 기존 요청·용량·도메인·robots 제한은
유지합니다. 100개 설정은 회당 상한일 뿐 하루 수집 한도가 아닙니다.

## 출처 실패 원인의 후속 코드 확인

운영 실행에서 기록된 DPC `network_or_redirect_failure:ValueError`는 수집기에서
재현됐습니다. 공식 URL이 승인된 동일 호스트 안에서 `https`→`http`→`https` 순으로
리디렉션됐고, 중간 HTTP 주소를 안전 검증기가 거부한 것이 원인이었습니다. 같은
승인 호스트·기본 포트·무인증 조건의 HTTP→HTTPS 업그레이드만 허용하고 모든 리디렉션
홉에 기존 호스트 검사, robots 검사, 요청 예산을 유지하도록 수정했습니다. 로컬에서
같은 공식 URL을 읽어 최종 HTTPS 문서까지 도달하는 것을 확인했습니다. 도착한 문서는
삭제 안내와 대체 자료 링크만 제공하고 게시일은 없어서 `requires_review=true`,
`ai_ready=false`로 보류됩니다. 이 수정은 네트워크 fetch 검증이며 운영 DB 재실행은
아직 하지 않았습니다.

ICO에서 실패한 URL도 관리형 환경에서 다시 읽었습니다. 공식 응답은 HTTP 200이지만
HTML에는 제목과 화면상 날짜만 있고 기사 본문 노드가 없습니다. 따라서 기존
`title_or_body_missing`은 이 응답에 맞는 fail-closed 결과이고, 빈 내용을 정상 기사로
저장하도록 완화하지 않았습니다.

리디렉션 수정 후 GitHub Actions에서 DPC만 같은 기간으로 수동 재시험했습니다.
[39567808560](https://github.com/parksunup/globaltrend/actions/runs/39567808560)은
54건 확인(기간 밖 51, 신규 2, 변경 1, 게시일 미확정 보류 3), 11페이지 후
`partial`로 끝났고 `coverage_complete=false`였습니다. 리디렉션 오류는 더 이상 나오지
않았지만 이 실행만으로 DPC 한 달 범위의 완전성은 입증되지 않았습니다. 새 초안이나
공개 보고서를 자동 생성하지 않았습니다.

## 최신 robots-aware 읽기 전용 probe

관리형 Codex 환경의 무쓰기 probe `5d73430f-0039-49b6-aee3-94afb9c0ec53`는 기존
9개 출처 모두에서 목록과 표본 상세를 파싱했습니다. 이 결과는 읽기 경로 확인일
뿐이며 운영 DB 수집·범위 완전성 증명이 아닙니다. OECD 표본은 화면 표시일
`2026-10-15`, HTML의 `datetime`은 `2026-10-14`로 달라 날짜를 미확정으로 두었습니다.
PPC 표본은 페이지 제목의 명시적 공표일 `2026-10-07`을 식별했지만 HTML 본문은 162자,
미열람 첨부 2건이었습니다. 첨부 PDF를 읽기 전에는 검토 필요·`ai_ready=false`로
남기도록 했습니다.

같은 코드의 GitHub Actions 무쓰기 probe [39570805523](https://github.com/parksunup/globaltrend/actions/runs/39570805523)
및 PPC 날짜 수정 후 [39571249650](https://github.com/parksunup/globaltrend/actions/runs/39571249650)은
각각 EDPB, CURIA, CNIL, ICO, DPC, PPC 6개 출처의 목록·표본 파싱을 통과했습니다.
반면 세 출처는 계속 runner 접근 단계에서 실패했습니다.

| 출처 | GitHub runner 결과 | 관측된 경계 |
|---|---|---|
| OECD | `http_403` | 개인정보 주제 목록과 상세 요청 모두 403 |
| FTC | `robots_fetch_failed:http_403` | robots.txt 요청이 403; 정책을 우회하지 않음 |
| PDPC | JSON 파싱 실패 | 공식 목록과 상세가 `text/html`, 0바이트 응답 |

무쓰기 probe는 모두 `operation_success=false`, `coverage_complete=false`이며 DB에
자료를 제출하지 않았습니다. 관리형 환경에서 접근되는 OECD·FTC·PDPC를 GitHub Actions
경로에서 성공했다고 간주할 수 없습니다. 외부 프록시나 새 서비스로 우회하는 설정은
추가하지 않았습니다.

따라서 이 검증으로 확인된 것은 일부 출처에서 제한된 수동 수집·DB 저장과 CI 경로가
동작한다는 점입니다. 9개 출처의 월간 범위 완전성이나 무인 정기 운영 준비 완료는
검증되지 않았습니다. 새 외부 서비스, 유료 API, 추가 출처, 예약 활성화, main 병합은
이 작업에서 적용하지 않았습니다.

무쓰기 probe의 전역 결과이며 운영 수집 성공 또는 범위 완전성을 뜻하지 않습니다.
