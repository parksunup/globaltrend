# 주간 팟캐스트 편집 지침

이 문서는 발행된 주간 동향을 바탕으로 두 진행자가 주요 소식 2~3건을 깊이 있게 설명하는 팟캐스트를 만들 때 따릅니다. 예시호처럼 서로 다른 시기의 자료를 이용한 테스트는 실제 주간 발행물과 분명히 구분합니다.

## 기준으로 삼은 NotebookLM 방식

2026년 10월 NotebookLM에서 세 개의 공식 출처(EDPB 자료 두 건과 사법재판소 보도자료)를 넣고 **심층 분석** 오디오 오버뷰를 생성했습니다. NotebookLM 화면은 두 호스트가 소스의 주제를 대화로 분석하고 연결하는 형식, 특정 주제에 집중하도록 지시하는 프롬프트 입력란, 출처 선택을 제공했습니다.

이 프로젝트는 NotebookLM 오디오를 자동 복제하거나 NotebookLM을 제품 안에 연결하지 않습니다. 테스트에서 참고한 제작 원칙은 다음과 같습니다.

- 먼저 출처를 고르고, 그 출처 안에서 이번 회차의 질문을 좁힙니다.
- 두 사람이 문장을 번갈아 읽는 데 그치지 않고 질문, 설명, 확인, 반론, 정정이 오가는 대화를 씁니다.
- 서로 다른 소식은 억지로 한 사건처럼 묶지 않습니다. 근거가 있는 공통 질문이 있을 때만 연결합니다.
- 오디오가 내용을 대신 결정하게 하지 않습니다. GlobalTrend 대본은 확인된 동향 자료에 근거해 사람이 작성·검토하고, Gemini는 승인된 대본의 음성 합성에만 사용합니다.

## 이번 회차에 넣을 소식 고르기

기본은 2~3건입니다. 세 건을 채우려고 중요도가 낮은 소식을 억지로 넣지 않습니다. 각 후보를 다음 질문으로 검토합니다.

1. 정보주체의 권리, 개인정보 처리 방식, 감독기관의 집행 또는 법제 변화에 미치는 영향이 큰가?
2. 기존 제도와 달라진 점 또는 독자가 이해할 만한 실제 쟁점이 있는가?
3. 공식 원문과 자료의 요약·근거가 충분하여 사실과 절차 상태를 설명할 수 있는가?
4. 고른 다른 소식과 중복되지 않으면서 회차의 관점을 넓히는가?

선택 이유는 편집 메모로 기록합니다. 자료가 부족하거나 날짜·절차 상태를 확정할 수 없다면 제외하거나 짧게만 언급합니다. 한 회차에 모든 소식을 담지 않아도 됩니다.

## 대본을 짜는 순서

1. **회차 질문을 정합니다.** 기사 제목을 나열하지 말고 청자가 실제로 궁금해할 질문으로 시작합니다.
2. **각 소식의 사실 카드를 만듭니다.** 무슨 일이 있었는지, 누가 발표·판단했는지, 날짜, 문서의 상태, 핵심 근거, 공식 원문 링크를 정리합니다.
3. **소식마다 다른 대화의 역할을 줍니다.** 한 소식은 판단 절차를 풀고, 다른 소식은 구체 사례를 검토하고, 또 다른 소식은 결정과 아직 남은 쟁점을 구분하는 식으로 질문을 다양하게 합니다.
4. **공통 맥락을 확인합니다.** 여러 소식이 실제로 공유하는 질문이 있는지 확인합니다. 없다면 각각의 맥락을 유지하고 전환만 자연스럽게 씁니다.
5. **처음부터 끝까지 읽어봅니다.** 같은 도입·요약을 반복하는지, 갑자기 다른 주제로 넘어가는지, 설명 없이 약어와 법률 용어가 쌓이는지 확인하고 고칩니다.

## 말하는 방식

- 진행자 1은 호기심 있는 청자의 질문을 대변합니다. 생활 언어로 묻고, 이해되지 않는 대목을 다시 확인합니다.
- 진행자 2는 분석을 맡습니다. 핵심을 먼저 답하고, 근거와 한계를 차분히 설명합니다. 두 역할은 회차에 따라 바꾸어도 됩니다.
- 질문의 모양과 답변 길이를 섞습니다. 짧게 확인하고 넘어갈 대목, 사례를 놓고 길게 따질 대목, 서로 다른 해석을 비교할 대목을 구분합니다.
- 기사 제목·리드·목록을 그대로 낭독하지 않습니다. 사실은 보존하되 대화에 맞게 다시 표현합니다.
- 군더더기 추임새, 억지 농담, 매 소식마다 같은 문장으로 시작하는 방식은 피합니다.
- 낯선 용어는 처음 나올 때 짧게 풀고, 뒤에서는 정한 한국어 용어를 일관되게 씁니다.
- 결론을 부풀리지 않습니다. 편집자의 해석은 확인된 사실과 구별해 표현합니다.

## 사실과 법적 상태 확인

각 소식은 다음을 서로 구분해서 씁니다.

- **확인된 사실:** 공식 발표·판결·문서에서 실제로 확인되는 내용
- **절차 상태:** 제안, 공개 의견수렴, 채택, 최종본, 판결의 본안·절차 판단 등
- **의미 해설:** 독자가 이해하도록 덧붙이는 설명. 사실이나 법적 결론처럼 단정하지 않음
- **남은 점:** 아직 결정되지 않았거나 원문만으로 확인할 수 없는 사항

특히 의견수렴 문서를 확정된 법적 의무로 말하지 않습니다. 법원의 소송 적법성 판단을 법 위반의 본안 판단으로 바꾸지 않습니다. 보도자료만 확인했다면 판결문 전문을 검토한 것처럼 쓰지 않습니다. 수치·당사자 의도·영향·향후 전망은 출처가 뒷받침할 때만 언급합니다.

## 낭독 분량과 마무리

- 기본은 주요 소식 2~3건을 이해하는 데 필요한 분량입니다. 시간을 채우려고 같은 사실을 반복하지 않습니다.
- 각 소식에는 사건의 의미뿐 아니라 적용 범위, 절차 상태 또는 남은 한계를 하나 이상 포함합니다.
- 마지막에는 세부 요약을 다시 읽지 않습니다. 소식들이 답한 질문과 서로 다른 법적 상태를 짧게 정리합니다.
- 공식 원문과 GlobalTrend 동향 페이지로 이어지는 링크를 제공해 청자가 직접 확인할 수 있게 합니다.

## 공개 전 확인표

- [ ] 2~3건을 고른 이유가 분명하고, 중복·약한 후보를 억지로 넣지 않았는가?
- [ ] 인명·기관·날짜·수치·법률 명칭이 원문과 맞는가?
- [ ] 초안·의견수렴·최종본·판결 절차와 본안을 정확히 구분했는가?
- [ ] 두 진행자가 각자 역할을 하면서 자연스럽게 질문과 설명을 주고받는가?
- [ ] 원문에 없는 법적 조언이나 확정적 전망이 들어가지 않았는가?
- [ ] 각 소식의 원문 링크와 GlobalTrend 상세 자료를 함께 확인할 수 있는가?
- [ ] 사람 검토 후 승인된 대본만 음성으로 만들고, 공개는 별도 발행 절차를 거치는가?
