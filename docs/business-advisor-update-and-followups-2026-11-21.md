## 2. 현재 11개 질문의 후속 질문 설계

기존 11개는 대분류로 유지합니다. 아래 후속 문항은 전 이용자에게 한꺼번에 보이지 않고, 답변에서 해당되는 갈래만 순서대로 표시합니다. 질문은 법률 결론을 묻지 않고 회사의 사실·절차·증빙을 묻습니다. 기본 선택지는 `예`, `아니요`, `잘 모르겠어요`, `해당하지 않아요`이며, `해당하지 않아요`에는 이유를 고르게 합니다. `잘 모르겠어요`는 미준수로 단정하지 않고 확인 과제를 만듭니다.

### 1) 데이터 파악 — 사업·적용 범위와 데이터 목록

**기존 질문:** 어떤 사람의 어떤 개인정보를 어디서 받아 어디에 보관하는지 정리되어 있나요?

1. 어느 국가에 제품·서비스를 제공하거나 현지 법인·직원·영업 거점을 두고 있나요? *(국가 다중 선택; 미국은 주 선택 포함)*
2. 현지 이용자를 대상으로 판매·광고·계약하거나 현지 언어·통화·배송·고객지원 등을 제공하나요? *(시장 적용범위 분기)*
3. 정보주체는 누구인가요? *(고객, 잠재고객, 직원·지원자, 아동, 환자, 사업자 담당자, 기타)*
4. 어떤 개인정보 항목을 수집·생성하나요? *(식별·연락처, 계정·기기, 결제, 위치, 건강, 생체, 아동, 추론·평가정보 등 복수 선택)*
5. 각 항목은 어디에서 얻고, 어느 시스템·국가에 저장되며, 누가 접근하나요? *(데이터 흐름표/시스템 목록 첨부 또는 모름)*
6. 대상자 수와 기록 수를 국가·연도별로 집계할 수 있나요? *(수치 기준이 있는 법제 분기)*

### 2) 목적·고지 — 목적별 설명과 실제 처리

**기존 질문:** 수집 목적과 이용 방법을 정하고, 해당 시장 이용자에게 알리고 있나요?

1. 개인정보를 사용하는 목적은 각각 무엇인가요? *(서비스 제공, 결제, 보안, 분석, 맞춤광고, AI 학습, 채용 등 복수 선택)*
2. 이용자가 정보를 입력하거나 서비스에 가입하기 전에 어떤 내용을 어디서 보나요? *(고지 화면·계약·개인정보 처리방침)*
3. 실제 앱·웹·직원 업무의 처리가 고지한 목적·데이터·수신자와 일치하는지 최근 대조했나요?
4. 원래 목적 외 분석·광고·모델 학습·계열사 공유를 하나요? *(예면 목적별 근거와 별도 고지·선택 분기로 이동)*
5. 목적·업체·데이터 항목이 바뀔 때 고지와 동의 문안을 갱신하고 기록하나요?

### 3) 처리 근거·동의 — 목적별 근거, 선택권, 철회

**기존 질문:** 각 처리 목적에 적용할 법적 근거와 동의가 필요한 경우의 절차를 정했나요?

1. 목적별로 어떤 처리 근거를 사용한다고 정했나요? *(동의, 계약, 법적 의무, 정당한 이익 등; 법률별 선택형 도움말)*
2. 동의가 근거인 처리에서 동의 전 목적·정보·수신자·보유기간을 설명하나요?
3. 선택 동의와 필수 처리를 분리하고, 거부해도 기본 서비스가 불필요하게 제한되지 않도록 했나요?
4. 동의를 철회하거나 설정을 바꾸는 방법을 처음 동의만큼 쉽게 제공하고, 철회 후 처리를 멈추나요?
5. 계약 이행·법적 의무 등 다른 근거를 쓰는 경우 그 근거가 실제 처리 목적에 맞는지 문서로 설명할 수 있나요?
6. 중국·EU·일본 등에서 별도 동의가 필요한 정보·수신자·이전 상황이 있는지 별도로 확인했나요? *(선택 시장별 분기)*

### 4) 민감·아동 정보 — 유형·연령·추가 보호

## 3. 상담앱이 현재 어떻게 구성되어 있는지

### 현재 코드 흐름

1. 사용자는 별도 Electron 데스크톱 앱에서 질문과 국가·지역을 선택합니다.

### 답변 시 검색 순서와 사용자 화면

1. 자가점검에서 이미 받은 시장·데이터·목적·공급자·이전·AI 정보를 질문에 함께 넘깁니다. 사용자가 바꾸거나 삭제할 수 있게 합니다.
2. 선택 관할에서 **현행 법령 DB → 최신 공식 기관 가이드·FAQ → 국제요정의 발행 동향(배경) → 사용자 안내서 → 유사 상담사례** 순으로 찾습니다.
3. 한 종류의 자료만으로 부족하면 다른 자료층에서 근거를 더 찾되, 서로 다른 시점·권위의 자료를 한 근거처럼 합치지 않습니다.
4. 답변은 `간단한 답 → 적용되는 사실과 전제 → 예외·국가 차이 → 지금 할 일 → 근거 목록`으로 표시합니다. 근거마다 자료종류·기관·관할·페이지/조항·발행/시행일·원문 링크를 보여줍니다.
5. 개정안·시행예정 규정은 현행 의무와 분리합니다. 자료가 검색되지 않는 경우 “의무 없음”이라고 하지 않고, 확인한 자료와 빠진 사실을 말합니다.
6. 앱의 사용자 ChatGPT 계정 연결은 모델 호출에 쓰는 인증 경로입니다. 자료를 스스로 학습시키거나 국제요정 DB에 자동 접속하는 기능은 아닙니다. 앱 서버가 근거를 검색해 질문과 함께 제공해야 합니다.

### 실제 구현 순서

1. 법령 DB 자료계약에 동향·가이드북·사례 자료종류와 기준일 필드를 더해, 기존 `published/official` 필터를 자료종류별 발행 상태에 맞게 확장합니다.
2. 가이드북 2종과 상담사례집을 페이지·사례 단위로 가져오는 색인을 만듭니다. 원문 페이지와 변환 텍스트 연결을 유지하고 표·도식은 PDF 페이지 확인 대상으로 표시합니다.
3. 현재의 단어 겹침 검색을 유지하더라도 먼저 자료종류·관할·기준일로 후보를 좁히고, 질문의 사실관계와 쟁점에 맞춰 근거를 재정렬합니다. 검색 결과에 점수만 보여주지 말고 왜 연결됐는지 근거 문장을 보존합니다.
4. API 입력에 질문뿐 아니라 자가점검 응답 요약을 선택적으로 포함하고, 개인정보가 불필요하게 저장되지 않도록 앱의 세션 정책을 정합니다.
5. 데스크톱 앱의 답변 지침에 “현행 법령 우선, 공식 안내와 과거 사례 구분, 근거 밖의 법적 기한 추정 금지, 불확실한 사실은 후속 선택 질문”을 넣습니다.
6. 사례집의 실제 상담 질문을 평가질문으로 사용해, 검색 출처·페이지 인용·현행성 표시·오답 방지·다국가 혼동 여부를 테스트합니다.
