## 구성과 연결

- 기존 9곳을 유지하고 새 11곳 모두 추적한다. 신규 7곳 활성 후보, 4곳 hold. 활성화 시 합계 16곳(Edge 12·클라우드 4), 보류 포함 추적 20곳이다.
- `expansion-routes.json`의 관찰한 기사 경로·목록·본문·게시일 선택자를 Edge/Python이 공유한다. 미검증 기관을 범용 CSS로 처리하지 않는다.
- EC reference와 본문 식별자를 대조하고 publishDate를 사용한다. eventDate·본문 사건일·수정일을 게시일로 쓰지 않는다. OAIC 추적 링크의 기사 주소만 보존한다.
- robots 파일 404·410만 규칙 없음으로 처리한다. 403, 5xx, 네트워크 실패와 명시적 금지는 계속 차단한다.
- 신규 DB 범위는 실행일-2부터 실행일까지. 기존 출처·임대·cursor·backlog·보고서를 초기화하지 않는다. 이전 HTML dispatcher는 중복 실행되지 않게 비활성 플래그를 유지한다.
- 기존 FTC snapshot·임대·멱등 저장은 유지하며 클라우드의 EC·유럽의회를 명시적으로 허용한다.
- 모든 보존 확정 자료는 기존 작성 RPC·한국어 검사·제출·작업실 재조회 경로로 처리한다. 미검수 원고는 공개하지 않는다.

## 발견 범위와 남은 검증

CalPrivacy는 현재 뉴스룸 10개 공지, 유럽의회는 RSS에 남은 항목, CAC는 공식 허브 노출 항목을 발견한다. 이 경로만으로 지연 게시나 당일 대량 게시의 전수 발견을 입증하지 않는다. OAIC·OPC의 날짜 내림차순 목록은 날짜 전부 확인·순서 유지 시만 이전 페이지를 멈추고, 날짜 불명/역순이면 계속 탐색한다. 기존 coverage_complete=false와 남은 범위 기록을 유지한다.

EDPS·PCPD·EU 이사회·EUR-Lex는 공식 본문·접근 문제가 해결되기 전까지 완료로 계산하지 않는다. 봇 확인 스크립트로 차단을 우회하거나 비공식 요약으로 원문을 대신하지 않는다.

## 2026-10-29 재개 후 추가 검증

- EC의 전체 최신 자료 API 대신 공식 검색 API `api/search`에 `datefrom`·`dateto`(공식 UI의 ddMMyyyy 형식)를 지정한다. 상한은 마지막 대상일 다음 날로 주어 하루 전체를 포함하고, 실제 저장은 상세 `publishDate`로 3일 범위를 다시 검사한다. 한국시간 2026-10-27~29 시험 검색에서 전체 18건의 날짜 조건 응답을 확인했다. 페이지 크기 10은 DB cursor에 URL 순서를 보존하기 위한 한 페이지 크기이며, 일일 처리 수 상한이 아니다.
- EC·유럽의회는 목록의 URL 순서와 다음 페이지를 기존 DB cursor에 고정한다. 다른 항목의 제목이나 순서가 바뀌어도 저장한 ordinal을 재개하며, 원문 본문과 제목은 실제 상세에서 읽는다. cursor는 기존 4,000바이트 제한을 준수한다. 실패 URL은 기존 backlog에 원자적으로 보존한 뒤에만 다음 위치로 이동한다.
- 유럽의회는 리디렉션 전후의 IPR 식별자가 같아야 한다. 같은 기사 제목 slug 변경만 허용한다. 다른 기사로 이동하면 원래 자료를 저장·해결 완료로 처리하지 않는다.
- 신규 11곳 등록·7곳 활성 구성·클라우드 2곳 분담·frozen cursor 허용/거절·공개 역할 실행 차단을 실제 DB 트랜잭션에서 검증한 뒤 전부 롤백했다. 운영 등록·활성화 완료를 뜻하지 않는다.
- 신규 캐나다 OPC 출처의 시험 원문 ingest → 작성 작업 생성 → 보존 확정 → 해당 작업만 선점까지 실제 DB에서 확인했다. 한국어 원고가 없는 상태의 성공 기록은 guard가 partial로 바꿨으며, 시험 자료와 이벤트는 모두 롤백했다. 실제 기사 한국어 작성·제출 성공과 구분한다.
