# 수집기 공통 저장 입구

이 단계는 EDPB·OECD·CURIA를 직접 방문하는 수집기를 켜는 작업이 아닙니다. 출처별 수집기가 확인된 자료를 **같은 규칙으로 Supabase에 저장하는 입구**를 만드는 작업입니다.

## 무엇이 달라지나요?

수집기는 자료 한 건을 찾으면 `ingest_source_item` 함수에 정리된 값을 보냅니다. DB는 다음 일을 한 번에 처리합니다.

1. 출처가 실제 등록돼 있고 사용 중인지 확인합니다.
2. 같은 출처의 같은 URL은 `source_items` 한 건으로 유지합니다.
3. 본문 SHA-256 해시가 같으면 재수집으로 보고 판본과 작업을 늘리지 않습니다.
4. 본문이 바뀌면 `source_item_revisions`에 새 판본을 보존합니다.
5. 그 판본을 입력으로 사용하는 `draft_jobs`를 한 번만 만듭니다.

따라서 수집기가 네트워크 오류로 같은 자료를 다시 보내도 동향 항목과 초안 작업이 중복되지 않습니다.

## 누가 호출할 수 있나요?

브라우저 방문자, 로그인 사용자, 팀원은 이 함수를 직접 호출할 수 없습니다. 서버에서 비밀키를 사용하는 신뢰된 수집 워커의 `service_role`만 호출할 수 있습니다. 실제 수집기를 만들 때도 비밀키를 브라우저 코드나 공개 저장소에 넣으면 안 됩니다.

## 아직 하지 않는 일

- EDPB·OECD·CURIA의 실제 페이지 구조 해석
- robots.txt와 이용조건 판단
- 외부 수집 스케줄 활성화
- Codex가 초안 작업을 가져가는 자동화

이 항목들은 동향 담당이 제출한 출처 규칙과 표본을 사람이 확인한 뒤 연결합니다.

## 수집기가 보내야 하는 핵심 값

| 값 | 뜻 |
| --- | --- |
| `source_id` | 등록된 출처 ID |
| `canonical_url` | 추적값을 제거하고 정규화한 공식 HTTP(S) URL |
| `title_original` | 원문 제목 |
| `content_text` | 허용 범위 안에서 추출한 비어 있지 않은 본문 |
| `content_hash` | 본문 UTF-8 바이트의 소문자 SHA-256 값 |
| `instruction_version` | 이후 초안 양식의 버전 |

게시일을 확인하지 못했다면 수집일을 게시일로 꾸며 넣지 않고 `null`로 보냅니다.
