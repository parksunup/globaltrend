# 자동 실행 기반과 활성화 전 검증

2026-10-21 기준. 이 문서는 기존 수집기의 실행 기반을 정리한다. 새 자료의 대량
수집, main 병합, 예약 등록·활성화는 이번 준비에 포함하지 않는다.

## 주 실행 경로

요청한 조건은 추가 유료 생성 API 없이 Codex가 한국어 초안을 작성하고 기존
Supabase 검수함에 제출하는 것이다. 이를 위한 주 경로는 **데스크톱 앱의 로컬
프로젝트 예약 작업 → 기존 Python 수집기 → Codex 편집 → 기존 Supabase RPC →
사람 검수함**이다. GitHub Actions는 기존 수동 진단·검증 경로로 유지한다.
두 경로의 예약을 동시에 활성화하지 않는다.

[OpenAI 공식 예약 작업 문서](https://learn.chatgpt.com/docs/automations?surface=app)는
데스크톱 예약 작업의 로컬 프로젝트/워크트리 실행과 앱·PC 실행 필요 조건을
설명한다. 웹 예약은 로컬 폴더를 유지하지 않는다. CLI는 예약 관리 화면을 제공하지
않는다. 현재 연결 도구에는 예약 생성 기능이 없으므로 이 저장소 변경으로 실제
예약이 생성되거나 구독 한도 이후 자동 재개되는 것은 아니다.

관리형 Codex cloud, 사용자 PC, GitHub-hosted runner는 서로 다른 접속 환경이다.
cloud에서 9곳을 읽었더라도 사용자 PC에서 동일하게 접근된다는 보장은 없다.
실제로 사용할 PC에서 다음 검사를 통과해야 한다.

## 준비한 실행 부품

- `scripts/collector/preflight.py`: DB 출처 승인·용량과 공식 목록/표본을 함께
  검사하는 읽기 전용 진입점. 원문·진행 위치·초안·운영 변수를 변경하지 않는다.
- `scripts/collector/environment.py`: 실행 결과에 실제 runner 종류·GitHub 실행
  ID·커밋을 기록한다. 로컬 프로세스를 예약 연결 완료로 표시하지 않는다.
- `docs/collector-task.md`: 매 실행 입력, 개인정보
  직접성 판단, Codex 작성, 형식·원문 대조, 정확한 작업별 제출 지침이다.
- 기존 CLI/RPC: 중복 방지, 원문 판본, 재개 cursor, 30분 임대·작업별 최대 3회
  시도, 기존 보고서 보호, 미검수·미발행 상태를 유지한다. 하루 10건 한도는 없다.
- GitHub 수동 workflow의 `mode=preflight`: 실제 GitHub runner에서 같은 사전검사를
  수행한다. Codex에서의 결과를 GitHub 성공으로 대신하지 않는다.

## 사용자 PC의 프로젝트 준비

Python 3.12와 Node.js 22를 사용하는 기존 프로젝트에 이 변경과 PR #39의 기반이
있어야 한다. 프로젝트의 Python 가상환경에
`scripts/collector/requirements.txt`를 설치한다. 새 서버나 외부 프로젝트는 만들지 않는다.
자격 증명은 보안 환경 변수 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`로 제공하며 값은
대화·예약 프롬프트·Git 파일에 넣지 않는다. GitHub Secrets를 추출하거나 로컬로
자동 전달한다고 가정하지 않는다. 연결이 없으면 앱의 보안 입력 절차로 제공해야 한다.

프로젝트 디렉터리에서 다음 명령을 실행한다.

```text
python -m scripts.collector.preflight --output work/collector-preflight.json
```

| 결과 | 의미 |
|---|---|
| `collection_preflight_passed=true` | 선택 출처의 승인·용량·목록/표본 해석 통과 |
| `activation_blockers` | 실행 승인, 예약 스위치, 예약 연결 등 별도 미충족 조건 |
| `runtime.actual=standalone-process` | GitHub runner 외의 명령 실행; 사용자 PC인지 관리형 cloud인지는 이 값으로 판별하지 않음 |
| `coverage_complete=false` | 사전검사는 기간 전체 수집을 증명하지 않음 |
| `automatic_korean_drafting=false` | 이 Python 명령이 생성 모델을 호출하지 않음 |

마지막 필드는 전체 계획에 한국어 작성이 없다는 뜻이 아니다. 작성은 예약 작업의
Codex 에이전트가 위 실행 지침을 읽고 수행한다. 예를 들어 접근 성공이어도 날짜 불일치나
미열람 PDF 때문에 개별 자료를 검토 보류할 수 있다. GitHub 외 환경에서는
`external_scheduler_unverified`가 남으며 이는 로컬 앱의 예약 등록 여부를 이
프로세스에서 확인하지 못한다는 뜻이다. GitHub PR 브랜치 실행에는 별도로
`workflow_not_on_default_branch`가 남는다. 앱 Scheduled의 실제
작업 상태·실행 이력으로 별도로 확인한다.

## 예약 화면에 넣을 준비된 작업

앱 사이드바의 `Scheduled`에서 로컬 프로젝트 작업을 준비한다. 이 프로젝트의
실제 로컬 폴더를 선택하고 실행 위치는 **로컬 프로젝트**를 사용한다. 이번 단계에서는
일시정지 상태로 저장할 수 있을 때에만 준비한다. 저장 즉시 활성화되는 UI라면
이번 단계에서는 등록하지 않고 아래 프롬프트만 보존한다. 주 실행기는 하나만 두며 기존 GitHub
`SCHEDULE_ENABLED=false`는 유지한다. 매일 07:17 한국시간은 기존 수집 일정이다.

사전검사 작업명: `globaltrend 자동 운영 사전검사`

저장할 프롬프트:

```text
docs/collector-task.md의 실행 지침을 사전검사 모드로 수행하세요.
이 프로젝트에서 AGENTS.md와 docs/collector-runtime.md를 읽고 기존 9개 출처의
읽기 전용 preflight를 실행하세요. 원문 수집 저장·초안 선점·제출은 하지 마세요.
실제로 실행된 컴퓨터, DB 연결·승인·용량, 출처별 접근 및 본문 해석 결과,
자동 운영 활성화에 남은 조건을 구분해 보고하세요. 비밀값을 출력하지 마세요.
예약이나 운영 스위치, source 설정, main, 배포·발행 상태를 바꾸지 마세요.
```

운영 프롬프트(별도 활성화 승인을 받은 뒤 사용):

```text
docs/collector-task.md를 읽고 기존 9개 출처의 수집과 한국어 미검수 초안 작성을
수행하세요. 먼저 실제 실행환경의 사전검사와 운영 게이트를 확인하세요.
승인값을 스스로 바꾸지 마세요. DB에 저장된 미완료 범위를 이어받고 정확한
원문 판본을 근거로 이 Codex 실행에서 한국어 원고를 작성하세요. 별도 생성 API는
사용하지 마세요. 한 건씩 검증·제출하며 하루 10건 한도를 두지 마세요.
기존 보고서를 덮어쓰거나 사람 승인·공개 발행·배포·main 병합을 하지 마세요.
실패·보류와 완료를 구분하고 저장된 보고서 ID 및 남은 작업을 기록하세요.
```

운영 프롬프트를 저장했다는 사실과 실제 자동 실행 성공은 별개다. 등록 확인,
실제 예정 시각의 실행, 그 실행환경의 출처 검사, 수집·작성·검수함 반영까지
확인한 뒤에만 해당 단계가 운영 중이라고 보고한다. 추가 사용 한도가 발생하지
않는다고 보장하지 않으며 기존 구독·무료 서비스 한도에서 중단·재개한다.

## 이번 준비에서 실제 확인한 범위

2026-10-21 현재 관리형 Codex cloud 환경에서 새 preflight를 실행했다. 기존 9개
출처 모두 DB 승인·용량 검사와 목록·표본 본문 해석을 통과했고 DB 크기는
25,291,923바이트였다. 원문 저장·초안 선점·제출·체크포인트 변경은 하지 않았다.
날짜 불일치·미열람 첨부 등의 개별 자료 보류 조건은 그대로 남는다.

이 환경의 세 운영 gate 값은 미설정/false였고 예약 스위치도 켜져 있지 않았다.
따라서 `collection_preflight_passed=true`라도 운영 승인 조건과 외부 예약 연결이
미확인이어서 종료 코드는 1이었다. 값을 임의로 true로 바꾸지 않았다. 이 결과를
사용자 PC나 GitHub runner의 성공으로 옮겨 적지 않는다.

수집기 회귀검사 88개와 예약 비활성 시 무네트워크·무DB 차단 검사를 통과했다.
데스크톱 예약 등록·실제 예정 시각 실행과 한국어 초안 제출은 이번 준비에서
실행하지 않았다. 준비된 지침이 실제 예약 작업에 읽혔다고도 주장하지 않는다.
