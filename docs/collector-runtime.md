# PC 전원과 독립된 클라우드 자동 운영 기반

2026-10-21 사용자 정정 반영. 기준은 `architecture.md` 3.1·3.2절과 사용자 최신
요구사항이다. 사용자의 PC가 꺼져 있고 데스크톱 앱이 종료돼 있어도 수집과 한국어
초안 처리가 클라우드에서 실행되어야 한다. 데스크톱 예약·로컬 cron·사용자 PC의
self-hosted runner는 이 요구의 해결책으로 사용하지 않는다.

## 실행 책임

| 단계 | 목표 실행 주체 | 상태 |
|---|---|---|
| 예약·영속 대기·재시도 | 기존 Supabase Cron + Queues | 실제 운영 설정·예약 실행 검증 미완료 |
| 공식 자료 수집·본문 확보 | 기존 Supabase Edge Functions 등 아키텍처의 클라우드 수집 실행부 | 현재 Python 구현과 해당 서버 실행부의 연결·실행 제한·9개 출처 접근 검증 미완료 |
| 한국어 초안 | 같은 프로젝트의 구독 내 클라우드 Codex 예약 작업 | 현재 계정의 예약 연결·도구 권한·무인 실행 검증 미완료 |
| 판본·임대·초안 저장 | 기존 Supabase RPC와 DB | 수동 연결 시험과 읽기 전용 사전검사 확인 |
| 코드 검사·회귀·접근 진단 | GitHub Actions | 검사 경로 구현. 실제 수집 스케줄러로 간주하지 않음 |
| 최종 공개 | 기존 사람 검수·승인·발행 절차 | 자동 발행하지 않음 |

수집은 Codex 편집 워커와 별도 실행한다. 수집기는 원문과 `draft_jobs`를 DB에 넣고,
클라우드 Codex 작업이 대기 작업을 당겨 한국어 초안을 반환한다. 웹 요청에서 Codex
앱을 깨우거나 사용자 PC로 콜백하는 경로는 두지 않는다. 구독 한도에 걸리면 초안을
대기시키되 수집과 이미 저장된 자료 열람은 유지한다. 하루 10건 작성 한도는 없다.

새 서버·외부 서비스·유료 생성 API를 도입하지 않는다. 이 문서는 기존 서비스에서
실행 가능한 연결을 검증하기 위한 기준이며 클라우드 실행부 배포·예약 활성화를
완료했다는 기록이 아니다. 사용자는 이후 실제 클라우드 예약·워커 연결과 무인 실행
검증까지 진행하도록 요청했다. main 병합·유료 API·추가 결제·새 외부 서비스·자동
발행은 계속 금지하며, 예약을 등록하거나 실행했다는 주장은 실제 증거로만 한다.

## 이번 PR에서 사용할 수 있는 부품

- `scripts/collector/preflight.py`: DB 출처 승인·용량과 공식 목록/표본을 함께
  읽는 사전검사. 자료 저장·초안 선점·체크포인트 변경은 하지 않는다.
- `scripts/collector/environment.py`: 실제 실행환경과 GitHub 실행 ID·커밋을
  결과에 기록한다. Python 프로세스가 있다는 사실로 cloud 예약을 추정하지 않는다.
- `docs/collector-task.md`: 클라우드 Codex 편집 워커의 작업·입력·제출 지침.
- 기존 CLI/RPC: 원문 판본·중복 방지·재개 cursor·30분 임대·작업별 최대 3회 시도·
  기존 보고서 보호·미검수·미발행 상태를 유지한다.
- GitHub 수동 workflow의 `mode=preflight`: GitHub 환경에서 수행한 진단으로
  남기며 Supabase나 Codex cloud 환경의 접근 결과로 대신하지 않는다.

## 실제 서버 환경에서의 사전검사

현재 Python 사전검사는 다음 명령을 사용한다. Python 3.12 및 저장소의
`requirements.txt` 환경이 필요하다. 이 명령은 진단용이며 Supabase Edge의 Deno
런타임에서 그대로 실행된다고 가정하지 않는다.

```text
python -m scripts.collector.preflight --output work/collector-preflight.json
```

`collection_preflight_passed`는 선택한 출처의 DB 승인·용량과 목록/표본 해석 결과다.
`coverage_complete=false`는 기간 전체 수집을 입증하지 않았다는 뜻이다.
`automatic_korean_drafting=false`는 Python 진단이 모델을 호출하지 않는다는 뜻이다.
`runtime.actual=standalone-process`만으로 사용자 PC인지 관리형 cloud인지 판별하지
않는다. `external_scheduler_unverified`는 외부 예약 연결을 확인하지 못했다는 뜻이다.

서버 자격 증명은 기존 보안 설정으로 제공하고 값을 대화·저장소·프롬프트에 넣지
않는다. GitHub Secrets나 cloud 환경 자격 증명이 다른 실행 환경에 자동 전달된다고
가정하지 않는다. 사용자 PC에 키를 설정하는 것을 운영 전제 조건으로 삼지 않는다.

## 클라우드 Codex 예약의 확인 조건

[OpenAI 예약 작업 공식 문서](https://learn.chatgpt.com/docs/automations?surface=app)는
웹 예약 작업이 연결 도구와 업로드 문맥을 사용하고, 로컬 폴더를 유지하지 않는다고
설명한다. 이 일반 기능 설명만으로 현재 계정에서 저장소·실행 환경·DB 도구를
갖춘 클라우드 Codex 작업이 예약 실행된다고 확정할 수는 없다.

클라우드 예약의 실제 등록 수단, 계정 가용성, 매 실행 사용할 도구·DB 권한을
검증해야 한다. 현재 이 세션에 예약 생성·조회 도구가 노출돼 있지 않다는 것은
현재 연결의 한계다. 이를 이유로 PC가 켜져 있어야 하는 방식으로 요구를 변경하지
않는다. 클라우드 예약 실행을 확인하지 못하면 그 단계는 미완료로 남긴다.

저장소의 실행 지침·문체·용어집은 작업 시작 시 고정 Git 판본에서 읽고, 영속 상태는
Supabase에 둔다. 임시 checkout·파일이 다음 실행에도 남아 있다고 가정하지 않는다.
클라우드 작업이 필요한 checkout·명령 실행·DB 도구를 실제로 사용할 수 있는지도
연결 시험에서 확인한다. 준비된 지침 파일을 실제 예약 작업이 읽었다고 주장하지 않는다.

## 완료 판정

1. 기존 클라우드 스케줄러와 수집 실행부의 등록·설정·접근을 확인한다.
2. 사용자 PC·앱과 무관한 예약 시각에 수집이 실행되고, 실행 ID·시각·출처별
   성공/실패·재개 상태가 서버 기록에 남아야 한다.
3. 클라우드 Codex 예약이 정확한 DB 작업을 가져와 한국어 초안을 작성·검증·제출해야 한다.
4. 검수함에 미검수 초안이 나타나고 기존 보고서를 덮어쓰거나 공개하지 않아야 한다.
5. 중단·구독 한도 후의 다음 클라우드 실행이 영속 DB 상태에서 이어받아야 한다.

위 단계별 증거가 없으면 전체 자동 운영 완료로 표시하지 않는다.

## 이번 준비의 실제 결과

관리형 Codex cloud의 읽기 전용 사전검사에서 9개 출처의 목록/표본 및 DB 승인·용량
검사를 통과했다. DB 크기는 25,291,923바이트였고 자료 저장·초안 선점·제출·진행
위치 변경은 하지 않았다. 이 환경의 운영 gate와 외부 예약 연결은 미확인이라
운영 준비 완료로 판정하지 않았다.

GitHub 읽기 전용 사전검사 39581720750에서는 DB 검사는 9곳 모두 통과했으나
OECD HTTP 403, FTC robots 요청 HTTP 403, PDPC 빈 응답 때문에 전체 진단이 실패했다.
두 환경의 결과는 서로 대체할 수 없다. 회귀검사 88개와 앱·DB CI는 통과했지만,
Supabase 예약 수집 배포와 클라우드 Codex 예약은 아직 검증되지 않았다.

실제 연결 점검과 현재 차단 사유는 [클라우드 실행 검증 기록](cloud-runtime-verification-20261021.md)에 남긴다.
