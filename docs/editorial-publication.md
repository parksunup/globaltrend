# 동향 초안에서 공개 페이지까지

`/work`는 팀 계정으로 동향을 작성하고 발행하는 화면입니다. 기존 `/`와 `/team` 검토 보드는 그대로 읽기용으로 사용합니다. `/public`, `/public/search`, `/public/trends/[id]`는 같은 Supabase 프로젝트의 **발행된 동향**을 읽습니다. 공개 화면에 예시 동향을 섞지 않습니다.

1. 편집자가 `/work`에 로그인해 활성 수집 출처를 고르고 공식 원문 URL, 원문 제목, 한국어 제목·요약을 입력합니다. `create_report_draft`가 원문 항목과 한국어 보고서를 한 트랜잭션에서 초안으로 저장합니다.
2. 편집자는 초안을 수정하고 **검수 요청**을 누릅니다. 이때까지 방문자는 보고서나 원문 항목을 읽을 수 없습니다.
3. 관리자는 원문 근거와 한국어 내용을 확인한 뒤 **승인**합니다. 승인만으로는 공개되지 않습니다.
4. 관리자가 **공개 발행**을 누르면 `reports.status`가 `published`가 되고 공개 홈·검색·상세에서 읽힙니다. DB 트리거가 승인 이력과 관리자 권한을 확인합니다. 방문자는 발행된 보고서에 연결된 원문 항목만 읽을 수 있습니다.

PR16의 동향 자료가 `main`에 병합되어 `data/trends/weekly-sample.json`과 출처별 표본 파일이 배포되면, `/work`의 **팀 제출 자료에서 시작** 목록에 예시 호에서 선정한 항목만 나타납니다. 항목을 고르면 공식 URL·게시일·한국어 초안이 입력창에 채워집니다. 두 파일의 URL과 게시일이 다르거나 필수 내용이 없으면 후보에서 제외합니다. **선택만으로 DB에 저장되거나 공개되지는 않습니다.** 편집자가 원문과 내용을 확인하고 저장해야 초안이 만들어집니다. PR16에서 선정되지 않은 표본과 날짜 불일치로 제외된 자료도 가져오지 않습니다.

이 흐름은 **동향 1건의 작성부터 발행까지**를 구현합니다. 팀 제출 파일에서 선택해 입력창을 채울 수 있지만 저장은 수동입니다. 자동 수집·Codex 초안 반환·PR 제출 파일의 자동 DB 가져오기, 주간호 편집·발행, 법제 한국어 번역 전문·비교표의 DB 등록·발행은 별도 연결이 필요합니다. PR 제출 화면의 피드백은 초안 저장·승인·발행을 수행하지 않습니다.

## 역할과 권한

- 편집자(`editor`): 원문 링크와 보고서 초안 저장·수정, 검수 요청.
- 관리자(`admin`): 편집 기능에 더해 승인·발행. DB 트리거가 직접 Data API 요청도 검사합니다.
- 익명 방문자: 발행된 보고서와 그 원문 항목만 읽기. `/team`의 출처·법제 목록·비교 기준 목록 공개 열람 정책은 별도로 유지됩니다.

기존 Supabase 프로젝트에는 활성 편집자가 1명이고 관리자 멤버십은 아직 없습니다. 운영자가 그 계정의 소유자를 확인한 뒤 `team_memberships.role`을 `admin`으로 정해야 발행할 수 있습니다. 암호나 서비스 역할 키를 GitHub 또는 클라이언트에 넣지 않습니다.

## 배포·검증

마이그레이션 `20261010015611_editorial_publication_pipeline.sql`을 앱 코드와 함께 배포합니다. Preview와 운영이 같은 Supabase 프로젝트를 바라보더라도 **Preview의 작성·검수·발행 서버 액션은 DB 쓰기를 차단**합니다. Preview는 화면과 읽기 동작을 확인하고, 실제 초안 등록과 발행은 운영 화면에서 실행합니다.

PR의 CI는 로컬 Supabase에 모든 마이그레이션을 재생한 뒤 `editorial_publication.test.sql`로 편집자·관리자·익명 방문자 권한을 검사합니다. 프런트엔드는 `pnpm test`, `pnpm validate:data`, `pnpm typecheck`, `pnpm build`를 통과해야 합니다. 실제 발행 시험은 권한이 확인된 계정과 검증용 원문 자료로 실행해야 합니다. 공개 검색은 현재 최대 최근 100건을 읽어 브라우저에서 필터링합니다. 자료가 많아지면 서버 페이지네이션과 DB 검색으로 바꿔야 합니다.
