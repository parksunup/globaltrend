# European Parliament 자료의 개인정보 동향 판정 절차

## 목적과 적용 범위

European Parliament Open Data API의 문서 수집은 후보 발견 단계입니다. API의 `pending`, `ai_ready`, 문서 제목, 개인정보 관련 단어의 존재는 개인정보 동향으로 채택했다는 뜻이 아닙니다. 초안 작업은 현재 원문 판본에 대한 편집 판정이 `accepted`인 경우에만 시작합니다.

이 절차는 API에서 과거에 저장된 문서를 재검토할 때와 향후 이 출처가 승인되어 수집될 때 적용합니다. 현재 출처 및 스케줄러 활성 상태는 데이터베이스의 `sources`와 `collector_cloud_routes`에서 별도로 확인합니다. 설정 파일의 출처 이름만으로 API 경로가 활성이라고 판단하지 않습니다.

## 문서별 판정

검토자는 현재 `source_items.current_revision_id`가 가리키는 본문을 읽고 다음을 확인합니다.

1. 개인정보 보호, 개인 데이터 처리, 정보주체 권리, 감시, 식별, 민감정보, 데이터 보안 또는 국경 간 이전에 관한 실질적인 쟁점이 있는가.
2. 문서가 제안·의결·채택·집행 중 어느 단계에 있는가. 질의서는 질문 자체와 집행기관의 답변을 구분합니다. 초안·수정안은 제안 내용으로만 기술합니다.
3. 기존 보고서와 같은 사건·법안·언어판·후속 판본인지 확인합니다. 같은 법안이라는 이유만으로 자동 중복 처리하지 말고, 새 판본의 구체적 변화가 별도 동향을 이룰 때만 별도 보고를 검토합니다.
4. 결론을 뒷받침하는 본문 위치와 원문 인용을 기록합니다. PDF의 쪽수·판본, 실제 읽은 범위 및 확인 시각을 남깁니다. 목차, 표지, 파일 길이, 검색 결과만 확인한 경우에는 본문 판정으로 간주하지 않습니다.

다음 분류를 기존 `public.record_trend_editorial_triage`로 기록합니다.

- `accepted`: 구체적인 개인정보 쟁점과 정책·법적 변화 또는 중요한 공식 절차 단계가 확인되고, 기존 보고서와의 중복 검토가 끝난 경우.
- `irrelevant`: 개인정보 관련 용어가 사회·정치적 의미로만 쓰였거나, 개인정보 처리와 무관한 문서인 경우.
- `low_significance`: 관련 주제는 있으나 일반적 언급·기존 원칙의 반복에 그치고 새로운 실질 변화가 없는 경우.
- `needs_review`: 본문이나 연결 자료가 부족하거나, 현재 판본·법적 단계·중복 여부를 확인할 수 없는 경우.

`accepted`가 아닌 판정은 초안 선점 대상이 아닙니다. 부족한 근거를 추정으로 보충하거나 일괄 수락·일괄 제외하지 않습니다.

## 초안 선점 전 검사

대기 작업을 `작성 가능`으로 보고하기 전에 현재 데이터베이스에서 아래 조건을 모두 확인합니다.

- job이 `pending`이고 시도 횟수가 격리 기준 미만이며 유효한 다른 임대가 없음
- job의 revision ID가 source item의 현재 revision과 같고 input hash가 해당 원문 판본과 일치
- 같은 revision에 대한 최신 편집 판정이 `accepted`
- 승인된 출처이고 원문 본문이 존재함
- 같은 사건·언어판·후속 판본을 포함해 기존 reports와 중복되지 않음

원시 `pending` 수, 관련성 미판정 또는 사람 검토 대기 수, 위 조건을 모두 통과한 선점 가능 수, 기존 제출 누적 및 이번 실행 제출 수를 별도로 보고합니다. 이 수치들은 서로 대체할 수 없습니다.

## 판정 변경과 감사 기록

문서 판정은 revision별로 기록합니다. 새 revision이 생기면 이전 판정은 새 본문에 대한 승인으로 재사용하지 않습니다. 판정에는 문서 ID와 revision ID, input hash, 판정 이유, 판정 기준 버전, 본문 확인 범위, 판정 시각을 남깁니다. 실패·미처리 작업은 정확한 사유와 job ID를 기록하고, 활성 임대는 기존 실패 RPC로 해제합니다. 제출 뒤에는 원문 revision과 보고서의 전체 제목·요약·본문, 작성 정책·검토기록, draft/미검수/미공개 상태를 재조회합니다.

## 출처 활성화와 역사 자료

European Parliament Open Data API의 수집 활성 여부는 출처 레지스트리 및 클라우드 경로에서 확인해야 합니다. 과거에 적재된 행과 대기 작업은 출처를 비활성화해도 자동으로 사라지지 않습니다. 과거 행은 이 절차로 판정하고, 대기열 통계에서는 적격 판정 전까지 작성 가능한 개인정보 동향으로 세지 않습니다. 이 절차만으로 출처를 활성화하거나 실행 일정을 켜지 않습니다.
