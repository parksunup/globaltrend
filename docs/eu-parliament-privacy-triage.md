# European Parliament 개인정보 관련성 판정 절차

## 목적과 경계

`eu-parliament-privacy-screen-v2`는 문서 전문의 명시적 개인정보·프라이버시 용어를 찾는 고정 어휘 사전입니다. AI, 사이버보안, 디지털 신원, 생체정보, 감시, 데이터 거버넌스라는 주제만 있는 문서는 후보로 올리지 않습니다. 다만 surveillance/spyware/monitoring 기술이 사람·언론인·활동가·반대자 등을 감시하거나 염탐하는 문맥과 결합하면 후보로 올립니다. 제품·시장·우주물체·어업 감시는 통과하지 않습니다. 화면 통과는 `candidate`일 뿐 관련성 승인이나 초안 작성 허가가 아닙니다. 비통과 문서는 수집 파이프라인에서 저장·작성 대기열로 보내지 않고 `topic_excluded` 수로 기록합니다.

화면은 영어와 스페인어, 프랑스어, 독일어, 이탈리아어, 포르투갈어, 네덜란드어, 폴란드어, 러시아어의 명시적 개인정보 용어를 포함합니다. 용어 사전이 새 문서 유형을 놓칠 수 있으므로, 새 언어·표현을 발견하면 본문 근거와 함께 테스트를 추가하고 버전을 올립니다. 사전 일치만으로 `accepted` 판정을 저장하지 않습니다. EP 추출기는 `ai_ready=false`, `requires_review=true`를 유지합니다. 정확한 게시일이나 텍스트 추출 성공만으로 개인정보 관련성이 승인되지는 않습니다. 기존 검토기록은 사용 당시의 screen version을 보존하고, 버전이 달라진 뒤에는 미처리 건에 새 버전을 기록합니다.

## 사람이 수행하는 문서 판정

1. 시작 전에 원본 `source_item_id`, 현재 `source_item_revision_id`, 본문 SHA-256, URL, 제목, 문서 유형, 작성일, 기존 editorial decisions, `reports`, draft jobs와 같은 문서의 언어판·수정판을 조회합니다. 이미 처리된 동일 revision은 재판정하지 않습니다.
2. 공식 원문 전문을 읽습니다. 보존 본문이 잘렸거나 원문 판본을 확인할 수 없으면 `needs_review`로 기록하고 구체적으로 누락된 범위를 적습니다. 제목·초록의 키워드만으로 결론 내리지 않습니다.
3. 실질적으로 식별·추론 가능한 개인 데이터의 처리, 정보주체 권리, 개인정보 보호 의무·집행·정책·법령·판결을 다루면 중요도와 신규성을 검토합니다. 문서에 개인정보가 부수적으로 언급되거나 주제가 디지털 정책 일반에 그치면 `irrelevant`로 판정합니다.
4. 개인정보 관련성이 직접적이지만 단순 일정·절차 공지이거나 독립적인 동향 가치가 낮으면 `low_significance`로 기록합니다. 정책 변화, 규제·집행, 법안·의회 결정의 구체적 변화가 있으면 `accepted` 후보가 될 수 있습니다. 애매한 범위는 `needs_review`입니다.
5. 동일 사건의 번역본, 정정본, 위원회·본회의 판본을 대조합니다. 실질적으로 같은 사건이면 가장 완전한 공식 원문 하나만 보존 후보로 남기고, 나머지 결정 이유에 대표 item ID와 판본 관계를 씁니다. 수정·후속 결정은 새 사실이 있을 때만 별도 동향으로 취급합니다.
6. `public.record_trend_editorial_triage`에 현재 revision ID와 본문 hash를 명시적으로 전달합니다. 각 source item/current revision 조합에는 최종 판정 하나만 남깁니다. 이유에는 전문에서 확인한 구체적 구절·절 또는 페이지, 개인정보와의 연결, 중요도, 중복 확인 결과를 포함합니다. `metadata`에는 `review_basis=full_official_text`, 실제 URL, 판본·쪽/절, 검토 시각, 중복 대조 ID, screen version을 기록합니다. 원문 확인이 불가능하면 확인한 범위와 실패 원인을 기록합니다.
7. RPC가 `stale_revision`, hash 불일치, 기존 report 보호, 출처 승인 또는 보존 gate 오류를 반환하면 값을 우회하지 않습니다. 해당 item을 실패·미처리로 두고 이유를 남깁니다. `accepted`는 기존 승인·임대 RPC가 허용할 때만 draft queue에 연결합니다. 이 절차 자체는 reports를 제출·승인·발행하지 않습니다.

## 재현 가능한 종료 확인

작업 범위는 시작 시점에 고정한 European Parliament item ID 목록입니다. DB 결과에는 범위 목록 hash, 시작 시각, 판정 버전, 각 item ID/current revision/hash/decision/reason, tool/RPC 결과를 기록합니다. 종료 시 범위 목록을 editorial decisions 및 현재 revision과 대조합니다. 모든 범위 item이 최종 판정 또는 구체적 명시 실패 상태를 가져야 하며, 미처리 수는 0이어야 합니다. 같은 item/revision에 상충하는 중복 결정이 있으면 완료로 세지 말고 원문을 다시 검토해 최종 결정을 기록합니다. 새로 들어온 자료는 고정 범위에 섞지 않고 다음 실행 범위로 분리합니다.
