# 법령 변경 점검과 검토 후 갱신

`/work/legal-updates`에서 공식 출처 점검 결과, 변경 후보 조항, 영향을 받을 수 있는 비교 기준을 확인합니다. 법제 작업실에는 점검 안내와 진입 링크가 있습니다. 정기 점검은 번역·비교표를 직접 수정하거나 공개하지 않습니다.

## 최신 상태부터 확인하기

2026-11-17 후속 확인 기준, 등록된 7개 기본법의 점검 대상 본문을 모두 확보했습니다. 한국은 현행·선정 본칙 127개와 부칙 13묶음이 일치하고, 중국은 공식 DB의 첨부 본문 74개 조문까지 확보했습니다. 아래 날짜별 실패 기록은 그전에 겪은 이력이며 현재 실패 목록이 아닙니다.

한국 참고 규정 9개도 공식 시행예정 본문과 일치함을 확인했습니다. AI 관련 7개는 2027-03-09 시행 개정, 인증 의무·과태료 관련 2개는 2027-07-01 시행 예외에 연결되며 현행 본문으로 합치지 않았습니다. 남은 쟁점은 캘리포니아 주 의회 법전의 추가 직접 대조와 모든 번역·비교표의 사람 검수입니다. 주간 점검은 main용으로 작성했으며, PR 병합 전 운영에서 실행 중이라고 표현하지 않습니다. Vercel 배포 성공과 실제 화면·API 확인도 구분합니다.

리드가 확인할 주소, 자료 위치, 검수 순서와 기술 확인의 한계는 [사람 검수 전 인계 안내](./legal-watch-review-handoff.md)에 모았습니다.

## 담당자 흐름

1. 법제 작업실의 **법령 변경 점검**을 엽니다. 변경 후보 외에도 확인 실패·제한된 확인·오래된 결과를 확인합니다.
2. 공식 출처에서 실제 개정인지, 현행·시행예정 판본인지 확인합니다. 첫 관측값을 자동으로 ‘번역과 일치하는 최신 법령’으로 인정하지 않습니다.
3. **Codex 수정안 작성 요청 복사** 또는 **검토 패킷 JSON 받기**로 수정안 작성에 필요한 정보를 준비합니다. 패킷은 원문 주소, 변경 식별자와 전후 해시, 기존 자료 기준 해시, 비교표의 기존 요약·예외, 번역 파일 위치를 포함합니다.
4. 기존 법제 담당 Codex 대화와 담당 브랜치 `feat/legal-corpus-foundation`에서 원문을 읽고 실제 수정안을 작성합니다. 이 기능은 새 한국어 법문을 추정해 생성하지 않습니다. 외부 유료 생성 API도 호출하지 않습니다.
5. 번역 전문과 비교표를 각각 검토합니다. 조항 번호·순서·조건·예외·수치·기한·출처와 조문 연결을 보존합니다. 조항 신설·삭제·미매핑 조항·부칙·메타데이터 변경은 전체 영향 검토로 넘깁니다. 조문 번호가 같아도 별도 하위법령과 같은 조항으로 단정하지 않습니다.
6. 기존 작업실에서 수정본을 저장하고 변경 내용을 확인한 뒤 별도로 공개합니다. 공개 권한·판본 충돌 검사·공개 전 기존 본문 유지·이력 보존은 기존 절차를 따릅니다. Preview에서는 저장·공개하지 않습니다.
7. 실제 사람이 번역과 비교표 검토를 모두 마친 경우 아래 검토 기록을 PR로 남깁니다. 기록을 추가하는 것만으로 공개되지 않습니다.

검토 패킷은 **수정안 작성 요청과 대조 자료**입니다. 새 번역문 작성·사람 검수·공개가 이미 완료된 결과물로 표시하지 않습니다. 같은 언어 모델이 작성한 요청문 자체도 원문 대조나 사람 검수를 대신하지 않습니다.

## 주간 점검

PDF 본문 추출은 무료 오픈소스 Poppler의 `pdftotext`를 사용합니다. workflow에서 `poppler-utils`를 설치하며 별도 유료 API를 호출하지 않습니다. 150쪽·입력 6 MB·출력 6 MB·20초 제한을 두고, 도구가 없거나 전체 조문·부속표를 확인하지 못하면 실패로 남깁니다. GitHub Actions 실행 시간·플랜의 무료 한도는 계정별로 별도 확인해야 합니다.

`.github/workflows/legal-amendment-watch.yml`은 main에서 월요일 09:30 KST에 실행하도록 정의했습니다. GitHub 사정에 따라 실행이 지연될 수 있습니다. main 병합 전에는 운영 정기 실행이 활성화됐다고 말하지 않습니다. `workflow_dispatch`로 수동 재실행할 수 있으며 이 workflow는 main에서만 동작합니다.

- 공식 출처는 `config/legal-watch/sources.json`에 등록합니다. 현재 기본법 7개를 등록했고 대상 수를 코드에서 7개로 제한하지 않습니다. 새 출처를 추가할 때는 공식 최신 판본 주소·분석기·전체 조문 최소 기준을 확인하고 초기 결과와 checkpoint도 함께 갱신합니다.
- 점검기는 해당 공식 HTTPS 호스트만 요청합니다. 실패·빈 응답·다른 문서·부분 법문·조문 수 급감은 ‘변경 없음’으로 바꾸지 않습니다.
- 최초에는 일본·영국·싱가포르의 선정 판본 주소를 별도로 대조합니다. 기존 판본을 읽지 못하면 ‘선정 판본 대조 미확인’ 상태로 남깁니다.
- 후속 실행은 직전 성공 관측과 비교합니다. 바뀐 원문이 다음 주에도 같더라도 미검토 사건은 유지합니다. 실패하거나 출처 설정이 바뀌어도 미완료 검토 기록을 삭제하지 않습니다.
- checkpoint에는 조문 식별자와 해시, 판본 메타데이터, 검토 대기 사건만 저장합니다. 외국 법문 전체·브라우저 쿠키·API 토큰·법제 작업실 비공개 원고를 저장하지 않습니다.
- GitHub Actions artifact `legal-amendment-watch`의 `checkpoint.json`과 `report.json`을 다음 실행에서 읽습니다. PR 실행 결과나 다른 workflow 결과는 기준값으로 쓰지 않습니다. 읽기 실패·만료를 빈 기준으로 숨기지 않고 실패시킵니다.
- artifact 보존 기간은 90일입니다. 정기 실행이 장기간 중단되어 마지막 기준이 만료되면 보관된 기준을 복원하고 다시 확인해야 합니다. 이전 성공 기록보다 오래된 artifact로 임의 후퇴하지 않습니다.
- 첫 정기 실행은 저장소의 `data/legal-watch/initial-checkpoint.json`을 이용해 최초 점검의 해시와 대기 사건을 이어받습니다.

## 작업실 결과 연결

정기 실행에는 GitHub가 제공하는 해당 저장소의 `github.token`과 `contents: read`, `actions: read`만 사용합니다. DB 키나 Vercel 관리자 권한은 필요하지 않습니다. 배포·DB 마이그레이션·발행 명령은 없습니다.

운영 서버는 기존 `TEAM_GITHUB_READ_TOKEN`으로 main의 이 workflow artifact를 읽습니다. 이 토큰에는 해당 저장소의 **Actions 읽기 권한**이 필요합니다. 토큰이 없거나 읽기에 실패하면 포함된 초기 수동 점검 자료임을 명시하고 최신 결과로 간주하지 않도록 안내합니다. 토큰은 브라우저·패킷·로그에 전달하지 않습니다. 서명된 artifact 저장소 URL 요청에도 GitHub 토큰을 전달하지 않습니다.

운영 페이지와 요약 API는 활성 editor/admin 팀 계정으로 제한합니다. Preview도 기존 작업실과 동일하게 팀 로그인이 필요하며, 공개 저장소에 포함된 원문 없는 초기 점검 결과만 사용합니다. 법제 작업실 안내는 5분마다 요약을 다시 확인합니다. 정기 결과가 14일 이상 지나면 경고합니다. 알림은 작업실의 안내와 GitHub 실행 요약이며 이메일·Slack 전송은 구현하지 않았습니다.

## 검토 기록

`config/legal-watch/reviews.json`의 `reviews` 배열에 실제 검토 후 다음 객체를 추가합니다. 아래 값은 형식 예시이며 실제 기록으로 복사하지 않습니다.

```json
{
  "eventId": "점검 사건의 실제 64자리 ID",
  "sourceDigest": "그 사건 afterDigest의 실제 64자리 해시",
  "translationCommitSha": "검토한 번역·비교표의 실제 40자리 커밋",
  "reviewedAt": "실제 검토 시각",
  "translationReviewed": true,
  "comparisonReviewed": true
}
```

두 검토 표시·근거 해시·사건 ID·커밋이 일치해야 대기 표시를 해제합니다. 최신 원문이 다시 바뀌면 새로운 사건이 생기며 이전 검토로 자동 완료하지 않습니다. 이 기록은 검토 이력이지 발행 승인이나 운영 DB 발행 기록의 대체물이 아닙니다. 자동 점검기는 검토 기록을 추가하지 않습니다.

## 2026-11-17 후속 점검과 수정안

[7개 법률의 근거·번역/비교표별 점검·남은 쟁점](../data/legal/amendment-review-20261117.md)을 확인합니다. 위 최초 점검의 실패 이력은 보존하며 이후 보완 결과는 아래와 구분합니다.

| 대상 | 후속 결과 | 한계 |
|---|---|---|
| 한국 | 기존 경로와 판본 지정·대체 주소를 재시도했으나 403/503/연결 오류 | 현행 원문 대조 미완료 |
| 일본 | 현재 공식 JSON 전체 1,327개 구조 노드 대조. 제2조 제8항·제63조 제1항 및 제공 부칙 제22묶음 제2~4조 번역, 일본 18개 비교 기준 수정안 | 사람 의미·법률 검수는 미착수, 자동 검토 완료 기록을 만들지 않음 |

| 싱가포르 | 현재 PDF와 2026-10-16 지정 PDF 원본 바이트 동일. 본칙 90개 단위와 11개 부속표 확보 | 모든 후속 규칙·미시행 개정의 적용 검토와 구분 |

EU는 공식 ELI의 Current consolidated version 식별자를 먼저 읽습니다. 이후 본문 연결이 실패했을 때만 고정 판본을 사용하고 `fixed_official_edition` 부분 확인 상태와 원래 오류를 명시합니다. 캘리포니아는 감독기관 안내에 연결된 법문 PDF 중 시행일이 지난 것을 선택하고, 미래 날짜·다른 호스트·규칙 파일은 제외합니다. URL은 허용된 공식 호스트만 요청합니다.

설정·분석기 변경 전의 미검토 사건도 유지합니다. 새 판본 수정안을 준비했더라도 사람 검토 두 건을 실제로 기록하기 전까지 대기 표시를 지우지 않습니다. 최신 수동 점검을 포함된 초기 자료로 제공하되, 운영 정기 결과와 혼동하지 않도록 출처 표시를 유지합니다.

## 2026-11-17 2차 보완: 중국 공식 DB 첨부 본문

중국 NPC DB의 `ossFile.ossWordPath`를 읽어 **같은 공식 호스트의 공개 파일 다운로드 경로**로 Word 첨부파일을 확보했습니다. 서명된 외부 저장소 URL이나 `urlIn`의 사설 IP는 사용하지 않습니다. 첨부 경로는 `prod/날짜/32자리 식별자.docx` 형식으로 제한하고 ZIP 내부의 `word/document.xml`만 크기·중복·암호화·XML 검사를 거쳐 읽습니다.

제1~74조 본문의 식별자가 DB 목차와 모두 일치했습니다. NPC의 기존 2021년 게시 본문과 조문별로 대조한 결과, 공백·장절 표제를 제외하면 제63조 4곳과 제69조 1곳의 세미콜론 폭만 달랐습니다. 이 폭 차이를 추가로 정규화하면 74개 조문의 문자 내용이 모두 일치합니다. 차이·대조 범위·해시는 [대조 기록](../data/legal/sources/pipl-attachment-check-20261117.json)에 남겼고 법률 개정이나 번역 의미 검수 완료로 표시하지 않습니다.

따라서 중국 점검은 목차·유효성만 확인하던 부분 상태에서 **선정 DB 항목의 본문·목차·유효성 대조**로 보완했습니다. 새 개정이 다른 DB 항목으로 게시되는지와 모든 하위규칙의 현행성은 이 점검의 범위 밖이며, 기존 번역·중국 18개 기준의 사람 검수 상태를 유지합니다. 위 1차 점검 기록의 첨부파일 연결 실패는 이력으로 보존합니다.

한국은 과거에 성공했던 본문 경로, 현행·판본 지정 경로, PDF·RTF 출력과 공식 기관 페이지를 재시도했지만 연결 시간 초과/502·503 또는 403을 받았습니다. 캘리포니아 주 의회 법전은 본문·개별 조문·법안·공개 디렉터리에서 `Just a moment` 브라우저 확인 페이지(403)를 반환했습니다. 이 둘은 해결 완료로 표시하지 않으며, Supabase 관리자 키나 Vercel 팀 권한 문제로 분류하지 않습니다. 일반 브라우저 시도는 이 환경의 인증서 신뢰 오류로 본문 확인에 이르지 못했고 TLS 검증을 끄지 않았습니다.

## 2026-11-17 한국 현행·선정 본문 확인과 자료 정리

현재 작업 환경의 연결 문제를 구분하기 위해 이미 허용된 한국·캘리포니아 공식 주소를 GitHub의 읽기 전용 진단에서 확인했습니다. 진단 workflow는 지정 담당 브랜치의 같은 저장소 PR에서만 동작하고 contents 읽기만 사용합니다. 원문 전체·쿠키·계정 키는 저장하지 않으며 일반 점검 workflow/main artifact만 신뢰하는 운영 결과 읽기 규칙도 유지합니다.

한국 공식 현행 안내가 선택한 `lsiSeq`와 `efYd`를 함께 읽어 본문으로 이동하도록 수정했습니다. 본칙과 부칙에 같은 조문 번호가 있어도 충돌하지 않도록 공식 문단 구조를 구분했고, 법률명·판본·최소 본칙 수를 확인합니다. GitHub 진단에서 현행·선정 본문의 127개 본칙과 13개 부칙 묶음 해시가 모두 일치했습니다. [읽기 진단 기록](../data/legal/sources/direct-source-diagnostic-20261117.json).

기존 한국 자료는 본칙 131개였으며 공백을 제외해도 9개 규정이 선정 본문과 달랐습니다. 현재 본칙은 확인된 127개로 정리하고, 이전 추가·상이 규정 9개는 판본 대조 참고로 보존했습니다. 원래 제출 자료 전체도 별도로 보존하며 미확정 규정을 현재 적용 법문으로 표시하지 않습니다. [차이·보존·판본 조정 기록](../data/legal/sources/pipa-edition-reconciliation-20261117.json). 사람 의미·법률 검수와 참고 규정의 별도 판본·시행일 확인은 미완료입니다.

캘리포니아 주 의회 법전은 이 진단에서도 403을 반환했습니다. 감독기관 편찬 PDF 확보와 추가 직접 대조 미완료를 화면 및 요약 API에서 구분합니다. 진단 workflow의 실행 성공은 모든 출처 확인 성공을 뜻하지 않습니다.

동일 진단에서 일반 브라우저도 시도합니다. TLS 검증을 유지하고 지정 주 법전 호스트 외의 요청은 차단합니다. CAPTCHA 조작이나 브라우저 식별자 변경 없이 본문 확보 여부만 기록하며, 실행 성공과 본문 확인 성공을 구분합니다.
