# 발행 절차 개선 과제

요청일: 2026-10-19. 총괄 관리자가 현재 절차가 너무 어렵고 번거롭다고 지적했습니다.

## 목표

코딩을 모르는 팀원이 클릭만으로 편하게 발행할 수 있어야 합니다. 자료마다 등록 → 검수 대기 → 승인 → 발행을 반복하고 같은 확인을 다시 요구하는 현재 절차를 개선합니다.

## 다음 개선 범위

- 자료를 선택하고 ‘선택 자료 발행’ 한 번으로 처리합니다. 중간 DB 상태 변경과 기록 저장은 시스템이 처리합니다.
- 총괄 관리자가 대화나 다른 경로에서 이미 검토·승인한 자료도 그 이력을 연결해 반복 검수를 요구하지 않습니다.
- 발행 전에는 선택 건수와 공개 범위를 간단히 보여 줍니다. 전체 문서를 다시 읽거나 항목별 체크박스를 반복해야 하는 절차를 강제하지 않습니다.
- 실패한 자료와 이유만 분명히 표시하고, 성공한 자료는 중복 발행하지 않습니다.
- 발행 후 ‘공개 페이지 보기’, ‘수정’, ‘공개 취소’를 쉽게 찾을 수 있어야 합니다.
- 검수자·검수일은 내부 감사 기록으로 저장하고 공개 화면에는 표시하지 않습니다.
- 팀 편집자는 수정·삭제할 수 있고, 최종 발행은 총괄 관리자가 결정합니다.

## 완료 기준

처음 사용하는 사람이 개발 도구·DB·GitHub를 열지 않고 자료 선택 → 발행 → 공개 결과 확인을 할 수 있어야 합니다. 다건 발행, 중복 클릭, 일부 실패, 수정 및 공개 취소를 실제 화면에서 검증합니다.

이 문서는 후속 개선 과제입니다. 현재 자료 발행과 별개로 전체 발행 화면을 이번 작업에서 재설계하지 않습니다.
