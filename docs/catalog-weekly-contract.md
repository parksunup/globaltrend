# 전체 동향 검색과 주간호 편집

사용자 정정(2026-10-28): 매일 수집한 동향자료 전수를 동향 검색에 등록하고, 그중 약 8개 주요 동향을 선정해 주간호로 발간합니다.

- 수집 한 건의 완료 기준은 원문 저장이 아니라 한국어 제목·요약·본문 검증 및 작업실 제출 완료입니다. 원문만 저장된 건은 처리 중 또는 실패이며 완료 동향으로 등록하지 않습니다. 작업실은 완료된 한국어 초안 전체를 주간 선정 여부와 무관하게 읽습니다. 공개 검색은 개별 검수와 발행을 마친 동향만 읽습니다. 원문과 실패 내역은 지우지 않습니다.
- 생산자는 collector_completion_gaps(대상시작일,대상종료일)를 확인하고 적격 미완료 자료를 작성·검증·제출할 때까지 재개합니다. 실패·검증 차단·실행 중단은 완료로 세지 않습니다. 개인정보 비관련 자료는 원문 전체 대조와 이유를 기록해 제외하며, 기사 수를 채우기 위해 의미 없는 원고를 만들지 않습니다.
- 한국어 초안은 전 자료 중 작성 가능한 자료에 대해 계속 작성·검증·작업실 제출합니다. 주간 선정 여부를 일일 초안 수량 제한으로 쓰지 않습니다.
- 검수 전 한국어 원고 전문은 공개하지 않습니다. 원문 수집 목록 등록과 한국어 보고서 공개 발행은 구분합니다.
- 월요일에는 직전 월~일 원문 발표 자료를 전수 비교합니다. 법령·정책 변화, 의미 있는 판결·제재, 새로운 기술과 개인정보 보호의 관계, 국내 정책상 중요성을 근거로 약 8개를 편집 선정합니다. 같은 발표·언어판은 묶으며 기관별 할당이나 최신순만으로 선정하지 않습니다. 적격 자료가 부족하면 수를 채우지 않습니다.
- 선정 보고서 ID와 구체적 선정 이유를 save_written_weekly_draft에 저장합니다. 주요 보고서가 미작성·게시일 불명확이면 그 사유를 남기며 새 주간호에 거짓으로 포함하지 않습니다.
- 기존 동향 작업실을 기본 `/work`로 옮기고, 그 안의 「주간 주요 동향 선정」 보기에서 원고 관리와 함께 처리합니다. 기존 `/team?role=trends`는 `/work`로 이동하며 별도 주간호 메뉴는 두지 않습니다. 작업실은 고유한 녹색 톤을 유지하고, 공개 주간호와 비슷한 목차·기사 본문 구조로 편집본을 보여줍니다. 법·정책 변경(5), 중요 판결·집행(4), 개인정보 처리 영향(3), 국경 간·신기술 쟁점(2)을 한국어 제목·요약·본문·주제 및 자료 유형에서 판별해 높은 순서의 최대 8건을 기본 선택합니다. 동점은 발표일·ID 순서로 정하며 기관별 할당은 하지 않습니다. 기계적 기본 선정은 사람이 중요도를 다시 검토할 출발점입니다. 아래에는 해당 주의 나머지 한국어 작성 완료 동향 전부를 같은 순서로 표시합니다. 체크 해제로 자리를 비운 다음 다른 자료를 체크할 수 있고, 8건 초과는 막습니다. 원제만 있는 자료를 대체 항목으로 채우지 않습니다.
- 동향 작업실에서 주간호 목차와 이유를 확인하고 교체·저장합니다. 자동 작업은 draft만 저장하며 공개 승인하지 않습니다. 공개 발간은 관리자 동작이고 모든 포함 기사가 검수·발행돼야 합니다. 글 주간호는 오디오 없이 발간할 수 있습니다.
- 주간호에 선정되지 않은 자료도 작업실에 남으며, 개별 검수·발행을 마친 뒤에는 공개 동향 검색에서도 조회됩니다. 과거 발간된 호는 자동 덮어쓰지 않습니다.

## 보존 확정에서 작성까지의 실제 연결

원문 발견/임시 저장은 수집 후보 단계입니다. 본문 전체를 읽어 개인정보 관련성과 중복·출처·날짜를 확인한 뒤 보존할 자료는 반드시 `collector_retain_for_draft(item_id,revision_id,input_hash,reason)`로 확정합니다. 이 RPC는 보존 결정과 기존 작성 작업의 연결을 같은 트랜잭션에서 보장합니다. 이후 선택 표본으로 다시 거르지 않습니다.

일일 Codex 작성 워커는 `collector_claim_retained_draft(worker)`를 반복 소비해 이 실행에서 한국어 원고를 직접 작성하고 기존 검사와 `submit_trend_draft`를 실행합니다. 수집 commit 이후에도 곧바로 작성 워커를 소비합니다. Edge가 원문을 저장한 경우에도 다음 생산 실행에서 보존 판정·동일 작성 큐로 이어집니다. DB 자체가 한국어를 생성하거나 별도 생성 API를 호출하는 구조는 아닙니다. 새 자료 저장 즉시 별도 Codex 프로세스를 깨우는 이벤트 기능이 생긴 것은 아니며 기존 클라우드 생산 예약이 작성 소비자입니다.

`collector_retained_draft_status()`가 unfinished=0이 될 때까지 확정 작업은 생산자 책임입니다. 유효 임대·원문 검증·실제 플랫폼 제한으로 이번 실행에서 끝내지 못하면 DB 작업과 오류를 보존해 다음 실행이 이어받습니다. `guard_retained_draft_completion`은 확정 자료에 한국어 원고가 없는데 생산자 요약이 success로 들어오면 DB에서 partial로 고칩니다. 재시도 횟수나 임대, 검증 gate를 초기화해 성공으로 꾸미지 않습니다.

DB에서 relevance_status를 relevant로 확정하는 순간에도 enqueue_retained_korean_draft 트리거가 동일 작성 작업을 자동 연결합니다. 원문 검증이나 작업 등록을 빼먹으면 보존 확정 자체가 실패하며, 작업 등록 없이 보존 자료만 남기는 분리 상태를 허용하지 않습니다.
