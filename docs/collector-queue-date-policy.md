# 수집 자료의 날짜와 작성 대기열

수집된 원문 판본은 근거 기록으로 보존합니다. 작성 대기 작업(`draft_jobs`)은 현재 판본에 대해서만 남깁니다. 새 판본이 오면 오래된 미완료 작업을 삭제하고 새 판본의 작업을 사용합니다. 해당 자료에 이미 원고가 있거나 개인정보 동향과 무관하다고 판정되면 미완료 작업을 삭제합니다. 제출된 작업과 기존 원고는 이 정리 과정에서 삭제하지 않습니다.

게시일은 `source_items.published_at`에 저장합니다. 원문 또는 목록에서 게시일을 명시적으로 찾으면 날짜를 채웁니다. 연도가 빠진 월·일 목록 표시는 발견 시점에서 가장 최근인 해당 날짜의 연도를 적용하고, `publication_date_resolution.year_inferred=true`를 남깁니다. 게시 의미의 관찰값을 출처에 관계없이 대조하며 서로 다른 게시일 후보가 충돌하면 임의로 하나를 선택하지 않습니다. 본문 속 사건일·판결일·수정일을 게시일로 바꾸지 않습니다. Trafilatura 날짜는 보조 후보로 사용하되 명시적 게시일 표시를 덮어쓰지 않습니다. 연·월만 확인되면 별도 `publication_month`에 저장·표시하고 일자를 만들어내지 않습니다.

게시일을 끝내 찾지 못해도 관련성과 원문 근거가 충분하면 한국어 동향 초안을 작성합니다. 원문 게시일은 비워 둡니다. 통합검색에는 포함할 수 있지만 날짜가 필요한 주간호 선정에는 포함하지 않습니다. 공개 화면은 사이트에서 원고를 발행한 시각을 원문 게시일로 대체하지 않습니다.

`ai_ready=false`는 게시일과 별개의 검토 신호입니다. 날짜가 없는 경우에는 이 값만으로 작성 선점을 막지 않으며 Codex 작성자가 실제 본문·첨부·관련성을 확인합니다. 날짜가 있는 자료에서 이 값이 false인 경우는 이번 정책으로 자동 승인하지 않습니다. 원문 부족, 중요한 미열람 첨부, 무관 자료, 지나치게 넓은 수집 범위 등의 원인을 자료별로 조사해 판단해야 합니다.

운영 DB 적용 시에는 날짜 복구·작업 정리 전후 건수를 기록하고, 제출된 원고 수와 공개 원고 수가 유지되는지 확인합니다. 적용된 migration: `20261114042710_collector_queue_date_policy.sql`.
