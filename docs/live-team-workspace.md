# 담당자 작업을 바로 확인하는 화면

## 담당자가 하는 일

1. 기존 담당 브랜치에서 Codex로 작업합니다. 동향은 `feat/trend-source-contracts`, 법제는 `feat/legal-corpus-foundation`입니다. 이 기능 때문에 새 브랜치를 만들지 않습니다.
2. Codex에게 결과를 해당 `data/trends/` 또는 `data/legal/`에 저장하고 검사한 뒤, **기존 담당 브랜치에 commit/push**하도록 요청합니다. 대화만 하거나 로컬에만 저장하면 다른 사람이 볼 수 없습니다.
3. 같은 사이트의 `/team?role=trends` 또는 `/team?role=legal`을 엽니다. 화면에 자료의 실제 커밋 번호와 연결 확인 시각이 표시됩니다. 화면은 2분마다 확인하며 서버 캐시 갱신까지 몇 분 걸릴 수 있습니다.
4. 자료를 읽고 기존 **의견 남기기**를 이용합니다. 이름은 선택이며 로그인은 필요 없습니다. 의견은 누구나 읽을 수 있으므로 개인정보·비밀은 쓰지 않습니다.

의견을 쓰는 도중 자료가 자동 갱신되어도 입력 중인 의견은 유지하며, **작성을 시작한 자료의 커밋**에 연결해 저장합니다. 화면에서도 이전 버전에 대한 의견임을 알립니다. 이미 발행된 것으로 간주하거나 최신 버전을 검토한 것으로 바꾸지 않습니다.

이후 자료 수정에는 PR 병합, Vercel 팀 초대, Supabase 관리 권한, 자료별 재배포가 필요하지 않습니다. 이 기능 자체를 처음 도입하는 배포는 한 번 필요합니다. 예전에 생성한 고정 커밋 배포는 코드까지 자동 변경되지 않습니다. 공유할 때는 기능이 도입된 사이트의 위 고정 경로를 사용합니다.

## 확인 화면과 공개 페이지는 다릅니다

- `/team`, `/legal-drafts`, `/legal-translation`은 공개 GitHub 저장소에 **이미 제출된 자료**를 읽는 검수 경로입니다. 미검수·미발행·공개 보류 표시 때문에 본문을 숨기지 않습니다. 이용조건 확인이 남았으면 본문 옆 확인 기록으로 남기며, 게시 허용을 확인했다고 주장하지 않습니다.
- 법제 검수에서 운영 DB의 예전 발행본으로 새 제출본을 덮어쓰지 않습니다. `public_release_status` 등은 기록이며 검수 열람의 승인 조건이 아닙니다.
- `/public`과 `/work`의 발행·편집 권한은 변경하지 않습니다. 이 기능은 자료 승인·대외 발행을 하지 않습니다. 비공개 DB 원문과 작업 초안을 익명으로 노출하지 않습니다.
- 이미 공개 저장소에 들어간 파일을 읽으므로 이 경로는 비밀 자료 보관소가 아닙니다. 저장소에 제출하지 않은 자료를 공개해 주는 기능도 아닙니다.

## Codex에 보낼 공통 지시

```text
기존에 배정된 제 담당 브랜치를 계속 사용하고 새 브랜치를 만들지 마세요.
작업 결과를 기존 데이터 형식에 맞춰 제 담당 data 폴더에 저장하고 검사를 실행한 뒤, 기존 담당 브랜치에 commit/push해 주세요.
검수 화면은 대외 발행과 별개입니다. 미발행·공개 보류 상태라는 이유만으로 조사 결과나 자체 번역 초안을 검수 화면에서 숨기거나, 검토하지 않은 부분을 검토 완료로 바꾸지 마세요. 실제 이용조건 쟁점은 근거와 남은 확인 사항으로 기록하세요.
기능이 도입된 사이트의 /api/team-workspace?role=제담당(legal 또는 trends)에서 commitSha가 실제 push한 커밋과 일치하는지 확인해 주세요. 오래된 커밋이나 오류가 나오면 반영 완료라고 하지 말고 그대로 보고해 주세요.
같은 사이트의 /team?role=제담당 주소를 검수 링크로 알려 주세요. 기존 피드백은 브랜치와 항목 ID로 읽어 반영하고, PR 병합·승인·발행은 하지 마세요.
```

`제담당`은 동향이면 `trends`, 법제이면 `legal`로 바꿉니다. API의 `items`는 조사 표본·출처/법제 목록, `documents.legal`은 비교 셀, `translations`는 전체 번역, `translationErrors`는 조문 파일 오류, `notes`는 보조 문서입니다. 피드백 조회는 기존 `/api/feedback?branch=...`를 사용합니다.

## 운영 및 실패 표시

서버가 허용된 두 브랜치의 SHA를 확인하고 그 SHA의 tree와 원본 파일을 읽습니다. 한 화면에 여러 커밋의 파일이 섞이지 않습니다. 새 출처 JSON과 새 법률 번역 JSON도 디렉터리에서 자동 발견합니다. 읽을 수 없는 번역 파일은 오류로 표시합니다. 보조 Markdown도 화면에서 읽을 수 있습니다.

공개 GitHub 읽기만 사용하므로 새 유료 API는 없습니다. 브랜치 목록과 불변 파일은 Next Data Cache로 공유하여 방문자마다 GitHub 요청이 증가하지 않도록 합니다. 선택적인 서버 전용 `TEAM_GITHUB_READ_TOKEN`은 공개 저장소 읽기 한도를 늘릴 때만 사용하며, 담당자에게 전달하거나 `NEXT_PUBLIC_`로 설정하지 않습니다. 토큰이 없어도 공개 저장소는 읽습니다. GitHub 한도·장애·브랜치 삭제 등 외부 사유까지 없어지는 것은 아니며 실패하면 원인 확인 안내와 마지막 성공본 여부를 표시합니다. 실패를 빈 자료 목록이나 발행 권한 부족으로 바꾸지 않습니다.

한 요청에서 파일 350개, 파일당 8MiB, 합계 24MiB를 넘으면 일부를 조용히 누락하지 않고 오류로 표시합니다. 규모가 커지면 분할 읽기를 추가해야 합니다. 서비스가 비공개 저장소로 바뀌면 별도의 접근 설계가 필요합니다.
