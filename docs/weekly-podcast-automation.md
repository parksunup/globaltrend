# 팟캐스트 제작과 게시

## 관리자 사용 순서

1. 국제요정 작업실의 **팟캐스트 제작**에 들어갑니다.
2. 화면에 자동으로 고른 메인 동향과 짧은 소식을 읽습니다. 필요하면 그 자리에서 다른 후보로 바꿉니다.
3. **제작 후 자동으로 게시**를 누릅니다. Google 로그인이 만료됐으면 열린 전용 계정 로그인 화면에서 직접 로그인합니다. 연결을 확인하면 같은 선택 자료로 제작을 이어갑니다.
4. **제작 현황**에서 진행 상황을 봅니다. 완성된 음성은 자동으로 국제요정에 저장되고 공개됩니다. 컴퓨터를 꺼도 클라우드 작업은 계속됩니다.

처음 한 번은 전용 Chrome 프로필에 작업실 연결 도구를 설치해야 합니다. 연결 도구는 Google 비밀번호를 읽지 않습니다. 로그인이 끝나면 전용 계정의 로그인 상태를 관리자 전용 API로 전달하고, 서버는 이를 암호화해 클라우드 제작기에 넘깁니다. 계정이 만료되면 제작 버튼에서 다시 로그인 화면을 엽니다.

## 실제 실행 경로

`공개 동향 → 화면의 후보 추천 → 관리자 선택 → 제작 요청 저장 → GitHub Actions의 NotebookLM MCP → 음성 회수 → Supabase Storage → 자동 게시` 순서입니다. 메인 주제는 한 건, 짧은 소식은 최대 한 건입니다. 관련 자료는 메인 주제의 근거로만 추가합니다.

개인용 NotebookLM에는 Google이 제공하는 이 용도의 공개 API가 없습니다. 클라우드 실행기는 고정 버전의 비공식 `notebooklm-py[mcp]` 서버를 사용합니다. MCP 서버는 같은 라이브러리의 도구 인터페이스이므로 로그인 정책을 우회하지 않습니다. NotebookLM 또는 MCP 도구의 변경으로 제작이 멈출 수 있습니다. 실패 시 작업실에는 상태가 남고, 확인 전에는 같은 음성을 무조건 다시 생성하지 않습니다.

클라우드에는 팟캐스트 전용 Google 계정만 사용합니다. 현재 연결된 쿠키는 Google이 다른 활성 세션을 쓰는 동안 짧은 시간에 무효화될 수 있습니다. 실행기는 별도로 보관한 전용 계정의 장기 인증 정보가 있으면 새 로그인 쿠키를 다시 만들도록 준비돼 있습니다. 그 정보는 GitHub Secret에서 실행 시에만 읽고 로그·저장소·공개 화면에 남기지 않습니다. 기관망에서는 장기 인증 발급에 필요한 Google 토큰 교환 주소로 연결할 수 없어 실제 발급을 완료하지 못했습니다. 이 발급을 위해 VPN이나 우회 접속을 사용하지 않습니다. **장기 인증 정보가 등록·검증되기 전까지는 로그인 유지 시간을 보장할 수 없습니다.**

운영 사이트에서만 자동 게시를 요청할 수 있습니다. Vercel Preview의 버튼은 게시를 막습니다. 공개 동향 원고의 변경 여부와 관리자 권한은 서버에서 다시 확인합니다. 게시된 회차는 작업실에서 취소할 수 있습니다.

## 관리자가 볼 수 있는 문제

| 화면 표시 | 뜻 | 조치 |
| --- | --- | --- |
| Google 로그인이 필요합니다 | 클라우드 로그인 만료 | 제작 버튼을 눌러 전용 계정으로 로그인 |
| 연결 도구가 없습니다 | 처음 연결 도구가 설치되지 않음 | 화면의 **첫 연결 안내**를 따라 한 번 설치 |
| 제작 대기 | 요청 저장 완료 | 기다리면 자동 실행; 컴퓨터를 꺼도 됨 |
| 확인 필요 | NotebookLM의 외부 요청 완료 여부가 불명확함 | 제작 현황을 확인하고 중복 제작을 피함 |
| 게시 완료 | 음성 저장과 공개 완료 | 공개 페이지에서 재생 확인 |

이전 브라우저 방식의 요청·수동 오디오 업로드 코드는 이미 만든 기록과 자료를 읽기 위해 남아 있지만, 새 회차의 기본 제작 화면에서는 선택하지 않습니다.
